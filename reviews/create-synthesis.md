# create-synthesis

## Цель тура

Провести по диалогу создания синтеза в ОСС (`DlgCreateSynthesis`, заголовок `tx.synthesis.short` → «Синтез»): две вкладки — **Аргументы** и **Отождествления** — заполнение метаданных операции, выбор аргументов и таблица отождествлений перед кнопкой **Создать**. Тур зарегистрирован на `route: '/oss'`, `autoStart: false`; запуск из `BadgeHelp` в `ModalForm` (`tourID={DialogTourID.CREATE_SYNTHESIS}`).

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `synthesis-tabs` | Частично: якорь на `TabList` (`data-tour='synthesis-tabs'` в `dlg-create-synthesis.tsx`). Labels вкладок совпадают: «Аргументы» / «Отождествления». Нет `onEnter` — ок, активна вкладка Аргументы по умолчанию. Title «Создание синтеза» ≠ заголовок диалога «Синтез». |
| `arguments` | explain | `synthesis-arguments` | OK по якорю: `data-tour='synthesis-arguments'` оборачивает `TabArguments` в первом `TabPanel`. Текст полей частично расходится с UI labels (см. P1). |
| `substitutions` | explain | `synthesis-tabs` | **Критическая проблема UX**: якорь повторяет `overview` (`synthesis-tabs`, placement `bottom`), но контент шага описывает вкладку **Отождествления** и таблицу под ней. Нет `onEnter` для переключения `activeTab` в диалоге; `TourStepController.changeTab` — только для вкладок страницы ОСС, не для вкладок модалки. Нет `data-tour` на панели отождествлений (`tab-substitutions.tsx`). В режиме `explain` overlay перехватывает клики — на последнем шаге клик в spotlight не переключает вкладку. Пользователь читает текст про таблицу, видя форму аргументов. |

**Проверка substitutions → synthesis-tabs:** в `index.ts` шаг `substitutions` явно использует `anchor: 'synthesis-tabs'` (reuse подтверждён). Это не ошибка конфигурации, а намеренный reuse без механизма показа целевой вкладки.

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0**

- Шаг `substitutions`, якорь `synthesis-tabs` при активной вкладке **Аргументы**: текст «На вкладке **Отождествления** заполните таблицу отождествлений… Сообщения под таблицей…» — таблица и поле валидации не видны; spotlight только на строке вкладок. Тур физически не демонстрирует объект объяснения.
- Шаг `substitutions`: «Создание выполняет операцию один раз, чтобы далее работало распространение изменений — как активация синтеза [IconExecute]» — смешивает кнопку **Создать** (`tx.general.create`) с **активацией** существующего синтеза (другая операция в графе ОСС). Риск: пользователь ждёт распространения сразу после «Создать» или не понимает, зачем потом активировать.

**P1**

- «Заполните название, **обозначение**…» (`arguments`) — в UI поле `tx.lib.alias` → **«Сокращение»** (placeholder «Введите сокращение»); подсказка валидации использует «имя» (`tx.cst.alias.validate`). «Обозначение» не совпадает с видимым label.
- «выберите операции-аргументы» (`arguments`) — секция в UI: **«Выбор аргументов»** (`tx.operation.argument.select.short`) с счётчиком `[N]`; вкладка — **«Аргументы»**. Термин «операции-аргументы» в UI не используется.
- «подсказки совпадений» (`substitutions`) — в домене/UI: **«предложения»** (`tx.substitution.suggestion.accept` / `decline`); «совпадения» блико, но не термин интерфейса.
- «аккуратно добавьте **дубликаты**» (`substitutions`) — в подсказке ромбовидного синтеза (`tx.synthesis.rhombus.hint`): **«дубликаты конституент»**; без «конституент» неясно, что дублировать.
- Title «**Создание синтеза**» (`overview`) vs заголовок модалки **«Синтез»** (`tx.synthesis.short`) — пользователь ищет «создание», видит только «Синтез».

**P2**

- «обычно **загрузки** или предыдущие синтезы» (`arguments`) — «загрузка» совпадает с терминологией справки ОСС; в списке операций тип отображается иконкой/имя операции, слово «загрузки» в UI списка не видно — допустимо для тура, но абстрактно.
- «после чего **создайте операцию**» (`overview`) — кнопка: **«Создать»**; «операцию» в label кнопки нет.
- «которые должны считаться одним **понятием**» (`substitutions`) — в контексте отождествлений домен чаще пишет **«конституенты»** / «определения понятий» (`tx.substitution.error.unequalExpressions`); «понятием» не ошибка, но расходится с соседним «конституенты схем-аргументов» в том же абзаце.
- EN copy (`content.en.tsx`): «**diamond** synthesis» — в i18n EN `tx.synthesis.rhombus` → «**Rhombus** synthesis»; RU «ромбовидный синтез» согласован с доменом.

## Пропущенные шаги

1. **Переключение на вкладку Отождествления** — structurally: `onEnter` + смена `activeTab` в диалоге (или `data-tour='synthesis-substitutions'` на панели `TabSubstitutions`) + якорь на таблицу, не reuse `synthesis-tabs`.
2. **Кнопка «Создать»** — overview обещает «создайте операцию», но нет шага на submit (`ModalForm` / `SubmitButton` без `data-tour`).
3. **Иконка валидации формы** — при незаполненном сокращении виден `IconAlert` с hint (`tx.cst.alias.validate` и др.); тур не объясняет, почему «Создать» disabled до заполнения полей и валидной таблицы.
4. **Предложения отождествлений** — copy упоминает подсказки под таблицей, но не кнопки «Принять предложение» / «Игнорировать предложение» в строках таблицы.
5. **Практический шаг `interact`** — ни одного; для диалога с двумя вкладками и таблицей типичен хотя бы interact «выберите вкладку Отождествления» или «добавьте отождествление».

## Избыточные / сливаемые шаги

1. **`overview` + `substitutions` на одном якоре `synthesis-tabs`**: оба `placement: 'bottom'`, spotlight в одной точке; `overview` уже описывает порядок «Аргументы → Отождествления → создать». Шаг `substitutions` логичнее якорить на содержимое вкладки (после добавления anchor) или слить rhombus/propagation-абзац в `overview`, оставив `substitutions` только для таблицы.
2. **`overview` при исправлении tab-switch**: если `substitutions` получит свой якорь и auto-switch вкладки, первый абзац `overview` («Сначала вкладка Аргументы, затем Отождествления…») остаётся нужным; второй про создание можно перенести в финальный шаг submit.
3. **`arguments`**: не избыточен — единственный шаг с якорем на форму; не дублирует `overview`, т.к. якорь `synthesis-arguments` vs `synthesis-tabs`.

## Топ-3 правки copy

1. **`substitutions` body (первый абзац)** — после технического fix вкладки: «На вкладке **Отождествления** заполните **таблицу отождествлений конституент**… Под таблицей — результат проверки; в строках — **предложения** (принять или игнорировать).» Убрать/перенести абзац про Create vs активацию в шаг submit.
2. **`arguments` body** — «название, **сокращение**» (не «обозначение»); «в блоке **Выбор аргументов** отметьте операции…» — в линию с `tx.lib.alias` и `tx.operation.argument.select.short`.
3. **`overview` title** — «Синтез» или «Диалог синтеза» (как `tx.synthesis.short`); в body: «…затем **Создать**» вместо «создайте операцию»; убрать из `substitutions` сравнение с активацией или заменить на: «После создания синтез в графе нужно **активировать** [IconExecute] для распространения изменений».

## Итог

Тур покрывает диалог синтеза в три explain-шага; якоря `synthesis-tabs` и `synthesis-arguments` существуют в `dlg-create-synthesis.tsx`. Reuse `synthesis-tabs` для `substitutions` подтверждён в `index.ts`, но без переключения `activeTab` и без anchor на панель отождествлений шаг **не показывает** таблицу — главный P0. Copy в целом согласован с labels вкладок («Аргументы», «Отождествления»), но расходится по полю **Сокращение** vs «обозначение» и путает **Создать** с **активацией**. Приоритет: (1) structural — вкладка + якорь на substitutions, (2) copy `substitutions` про propagation/активацию, (3) copy `arguments`/`overview` по терминам UI. Отдельный шаг на «Создать» и опциональный `interact` усилят тур без раздувания текста.
