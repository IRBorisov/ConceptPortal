# sandbox-passport

## Цель тура

Короткий гид по вкладке «Паспорт» в Песочнице (`/sandbox`): что задаёт паспорт локальной демо-схемы и модели, как править название/сокращение/описание и что показывает боковая панель статистики. Явно не покрывает: доступ, владение, версии, экспорт в библиотеку, сброс — это в других турах/меню (см. комментарий в `index.ts`).

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `tab-passport` | OK: якорь на вкладку «Паспорт» (`tx.lib.item.passport`), `onEnter` открывает паспорт. Замечание: title шага «Паспорт Песочницы» ≠ label вкладки «Паспорт». |
| `form` | explain | `passport-form` | OK с замечаниями: форма совпадает с полями; кнопка — `tx.general.save` («Сохранить») + `IconSave`. Не сказано про Ctrl+S (в UI работает). «Название» в UI — placeholder/aria-label, не label как у «Сокращение»/«Описание». |
| `stats` | explain | `passport-stats` | Проблема текста: якорь верный (`ViewModelStats`), но copy не отражает четыре заголовки панели (Содержание / Схема / Корректность / Модель) и сводит всё к «конституент схемы + проблемы модели». |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P1 — «Паспорт Песочницы» vs вкладка «Паспорт»**  
Цитата: «Паспорт задаёт название…» (title: «Паспорт Песочницы»).  
В UI вкладка: «Паспорт»; в форме заголовок h2: «Песочница». Ни один видимый label не «Паспорт Песочницы» — пользователь ищет несуществующую подпись.

**P1 — шаг `stats`: структура панели не совпадает с текстом**  
Цитата: «Боковая панель показывает счётчики конституент схемы и проблемы модели».  
В UI четыре раскрываемые блоки: «Содержание» (конституенты), «Схема» (базовые/сложность), «Корректность» (проблемы схемы), «Модель» (модельные проблемы + базис). Текст не называет «Корректность» и «Содержание», смешивает схему и модель в одну фразу.

**P1 — шаг `stats`: примеры проблем урезаны**  
Цитата: «например неопределяемые без интерпретации или ошибки вычисления».  
«Неопределяемые без интерпретации» = UI (`tx.concept.basic.validate.noInterpretation`) — точное совпадение.  
«Ошибки вычисления» близко к «Ошибка» / «Ошибка при вычислении», но в панели «Модель» также «Нарушенные аксиомы», «Неверные данные», «Пустое значение» — в `model-passport` они перечислены, здесь нет.

**P1 — шаг `form`: сохранение без Ctrl+S и без слова «Сохранить»**  
Цитата: «Изменения хранятся локально; [иконка] применяет их к данным Песочницы».  
В `schema-passport` / `model-passport`: «Сохранение — [иконка] или Ctrl + S». Здесь только иконка без «Сохранить» и без шортката; кнопка disabled до изменений — это не объяснено.

**P1 — шаг `form`: «хранятся локально» vs «применяет»**  
Цитата: «Изменения хранятся локально; … применяет их».  
До клика «Сохранить» правки только в форме (`isModified`); «локально» звучит как автосохранение в браузер. Нужно явно: «сохраняются в данные песочницы в браузере после Сохранить».

**P2 — шаг `form`: поле «Название»**  
Текст перечисляет «название, сокращение, описание» — в UI «Сокращение» и «Описание» с label, «Название» только placeholder в поле без label — визуальный диссонанс с текстом тура.

**P2 — шаг `overview`: дублирование с `sandbox-intro`**  
Цитата intro (`passport`): «задаёт название, сокращение и описание этой демонстрационной схемы и модели».  
Почти тот же смысл; intro уже ведёт в subtour `sandbox-passport` — второй раз тот же контекст.

**P2 — BadgeHelp на форме**  
`BadgeHelp` с `HelpTopic.UI_SCHEMA_CARD` («Паспорт схемы») и тур `sandbox-passport` — help-топик про библиотечную схему, не про Песочницу; тур не упоминает иконку справки.

**P2 — даты в форме**  
Под полями видны даты создания/обновления (`tx.general.date.creation` / `updated`); тур их не затрагивает — не критично для slim-тура, но молчание при видимых метаданных.

## Пропущенные шаги

1. **Ctrl+S** — реализован в `TabItemCard`, в sibling passport-турах в copy — здесь нет.
2. **Четыре категории статистики** — минимум одна строка по блокам «Содержание», «Схема», «Корректность», «Модель» (как в `schema-passport` stats для схемы).
3. **Заголовок формы «Песочница»** — отличие от библиотечного паспорта; тур говорит «Паспорт Песочницы», UI — «Песочница» + вкладка «Паспорт».
4. **Практический шаг `interact`** — ни одного; для паспорта допустимо, но пользователь не пробует «изменить → Сохранить» (в отличие от туров с `mode: 'interact'`).
5. **Связь проблем статистики с вкладками** — индикаторы на «Список»/«Данные» не упомянуты (опционально для slim-тура).

## Избыточные / сливаемые шаги

1. **`overview` + `form`** — при standalone-запуске оба нужны (разные якоря: вкладка vs форма). При входе из `sandbox-intro` → subtour `overview` частично дублирует intro-шаг `passport`; можно сократить `overview` до одной фразы про локальность и отсутствие библиотечных полей.
2. **`overview`** — если цель только «slim passport», шаг можно слить с `form`: открыть паспорт и сразу объяснить поля на `passport-form`, а отличие Песочницы — в первый абзац `form`.
3. **`stats`** — не избыточен (registry: passport-туры заканчиваются на `passport-stats`), но второй абзац «Раскройте категории…» generic; без первого абзаца с именами категорий шаг слабый.

## Топ-3 правки copy

1. **`stats` body** — заменить сводную фразу на соответствие UI: четыре блока («Содержание», «Схема», «Корректность», «Модель»), примеры проблем модели как в `model-passport` (неопределяемые без интерпретации, нарушенные аксиомы, неверные данные, ошибки вычисления).
2. **`form` body** — «Сохранение — [IconSave] «Сохранить» или Ctrl + S»; уточнить: правки в песочницу в браузере только после сохранения, не при вводе.
3. **`overview` title/body** — title «Паспорт» (как вкладка) или «Вкладка Паспорт»; в body: «данные только в браузере, без доступа и владельца библиотеки» — оставить, это ключевое отличие slim-тура.

## Итог

Тур технически корректен: три шага, якоря существуют в sandbox UI, `onEnter` открывает паспорт, финал на `passport-stats` по registry. Copy в целом context-neutral и согласован с EN. Главные пробелы: **несовпадение названия шага с UI** («Паспорт Песочницы»), **упрощённое описание статистики** без четырёх видимых категорий и полного набора модельных проблем, **слабее sibling-тура по сохранению** (нет «Сохранить» / Ctrl+S и границы «в форме vs в данных»). Критичных P0 (битый anchor, неверный route, вводящий в заблуждение термин домена) нет. После правок copy тур остаётся slim; отдельные шаги про доступ/версии не нужны. Приоритет: `stats` → `form` → `overview` title.
