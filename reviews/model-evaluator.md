# model-evaluator

## Цель тура

Показать вкладку **Расчет** (`RSModelTabID.EVALUATOR`): проверка и вычисление произвольных выражений на данных текущей модели без изменения конституент и их интерпретаций. Три шага: обзор вкладки → панель кэша/пересчёта → поле выражения и результат. Тур не `autoStart`; доступен из `BadgeHelp` на панели вкладки и как subtour из `sandbox-intro` (шаг `evaluation`).

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `tab-evaluation` | **OK по якорю и названию вкладки** (`tx.general.evaluation` → «Расчет»). Текст совпадает с UI-лейблом и help-меню. **Минус:** не отделён от вкладки «Данные»; «ЯРЭ» без пояснения при прямом запуске тура. |
| `tools` | explain | `model-evaluator-tools` | **OK по якорю** (кэш + «Пересчитать модель»). **Минус:** copy про «включает/отключает кэш» не совпадает с подсказкой кнопки («Отключить кэш вычислений»); иконка кэша в туре всегда в состоянии «включен». |
| `form` | explain | `model-evaluator-form` | **Якорь OK**, охватывает форму целиком. **Серьёзные минусы copy:** неверная геометрия блоков (типизация «ниже»); кнопка запуска — не «статус», а «Не вычислено»; просмотр результата — текстовая кнопка «Просмотр значения», не иконка базы данных. |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0 — вводит в заблуждение, расхождение с UI**

- «Откройте результат в … **диалоге просмотра значения**» + `IconDatabase` — в форме кнопка **«Просмотр значения»** (`tx.rslang.value.view`), без иконки базы данных. `IconDatabase` на этой вкладке — иконка **кэша** на панели инструментов.
- «**Ниже** появятся типизация, ошибки и значение» — в `form-evaluator.tsx` поле **«Типизация»** стоит **над** редактором выражения («Формальное определение»); ошибки в зоне выражения; значение — в нижнем блоке. Порядок в copy неверный.

**P1 — ясность / слабое совпадение с лейблами**

- «Вкладка **Расчет** … выражения **ЯРЭ**» — при запуске тура с вкладки (не из sandbox-intro) **первое упоминание ЯРЭ без расшифровки** (язык родоструктурных экспликаций / родоструктурное выражение). В туре `model-value` ЯРЭ не используется.
- Нет явного контраста с вкладкой **«Данные»** (`model-value`): там задают и сохраняют значения **конституент**; здесь — **любое** выражение, данные модели не меняются. Пользователь, прошедший только этот тур, легко путает две вкладки (общие «пересчитать модель», «статус», «просмотр значения»).
- «нажмите … **статус**» (`TourHelpLink text='статус'`) — на кнопке текст **«Не вычислено»** (`tx.evaluation.status.notProcessed`), не слово «статус». Ссылка ведёт на help про статусы вычисления, но не совпадает с видимым лейблом.
- «**включает или отключает** кэш вычислений» — подсказка кнопки только **«Отключить кэш вычислений»**; состояние «кэш включен» в UI не названо.
- Подсказка кнопки вычисления в форме: **«Сохранить и вычислить»** (`tx.rsexpression.saveAndCalculate`) — на вкладке Расчет **ничего не сохраняется**; тур молчит о вводящей в заблуждение подсказке (общий компонент с вкладкой Данные).

**P2 — полнота / дубли**

- Не упомянут **Ctrl + Q** — в `form-evaluator` есть обработчик запуска вычисления по этой комбинации.
- Не упомянуты **экспорт** результата (буфер / JSON), счётчики **итераций и кэш-попаданий** (есть в help `HelpRSModelEvaluatorRu`).
- Не упомянуты иконки панели выражения: **граф ступеней**, **дерево разбора**, **клавиатура/текст** — перечислены в help, но не в туре (для 3-шагового тура допустимо как P2).
- Шаг `tools`: **Alt + Q** дублирует тур `model-value` и teaser в `sandbox-intro` — избыточность при последовательном прохождении.

## Пропущенные шаги

| Что | Почему важно | Приоритет |
|-----|--------------|-----------|
| Отличие от вкладки **«Данные»** | Главный когнитивный разрыв: две вкладки с пересчётом, статусом и просмотром значения | P1 — лучше в `overview`, не отдельный шаг |
| Правильная геометрия UI: типизация **сверху**, статус **между** выражением и значением | Текущий copy вводит в заблуждение | P0 — правка `form`, не новый шаг |
| Кнопка **«Просмотр значения»** (и что диалог недоступен для некоторых типов) | Единственный путь к структурированному разбору; сейчас описан неверной иконкой | P0 — правка `form` |
| **Ctrl + Q** для вычисления | Реальный shortcut; на «Данные» — Ctrl+Q для одной конституенты | P2 |
| Панель выражения: AST / граф типов / отображение текста | Есть в help и UI; опционально для углублённого тура | P2 |

Отдельный шаг для панели выражения (`ToolbarRSExpression`, якорь `concept-tools` — общий с редактором концепта) **не рекомендуется** без нового `data-tour` на вкладке evaluator: якорь вводит в контекст концепта.

## Избыточные / сливаемые шаги

| Шаг | Вердикт |
|-----|---------|
| `overview` | **Оставить.** Нужен при запуске с `BadgeHelp`; даёт контекст вкладки. |
| `tools` | **Оставить**, но можно **слить с `overview`** в один шаг на `tab-evaluation`, если цель — минимальный тур (2 шага): обзор + кэш/пересчёт в одном абзаце, `form` — отдельно. Сейчас 3 шага зеркалят `model-value` — структурная симметрия оправдана. |
| `form` | **Оставить** — основной сценарий. Не дробить на typification / expression / value без новых якорей. |
| Пересечение с `sandbox-intro` → `evaluation` | Teaser дублирует `overview` («проверяет произвольные выражения ЯРЭ…»). **Норма** для subtour; при прохождении intro+c subtour пользователь видит overview дважды — **P2**, не убирать без смены intro. |

## Топ-3 правки copy

1. **`form` — просмотр результата:** заменить «диалог просмотра значения» + `IconDatabase` на «кнопку **Просмотр значения**» (как в UI), убрать иконку базы данных.
2. **`form` — порядок и запуск:** «Введите выражение (**Формальное определение**) и нажмите кнопку **Не вычислено** (или Ctrl+Q)»; «**Сверху** обновится типизация, в поле выражения — ошибки, **ниже** — вычисленное значение».
3. **`overview` — отличие от «Данные» и ЯРЭ:** одно предложение: «В отличие от вкладки **Данные**, здесь не редактируют значения конституент — только проверяют **родоструктурные выражения (ЯРЭ)** на текущих данных модели.» (или ссылка на help по ЯРЭ, если есть тема).

Дополнительно (четвёртая, если в топ-3 не влезает): **`tools`** — «Кнопка кэша (**иконка базы данных**) отключает кэш; при включенном кэше иконка цветная» — согласовать с односторонней подсказкой UI.

## Итог

Тур **технически корректен**: якоря, `onEnter` на вкладку Расчет, симметрия с `model-value`. **Критичные проблемы — в шаге `form`:** неверный порядок блоков, несуществующая иконка для просмотра значения, абстрактное «статус» вместо «Не вычислено». **Стратегическая проблема — в `overview`:** нет отличия от вкладки «Данные» и нет вводного пояснения ЯРЭ при прямом запуске. После правки copy (без новых шагов) тур достаточен для базового onboarding; углублённые элементы (AST, экспорт, отладочные счётчики) остаются в help — сознательно или как P2.
