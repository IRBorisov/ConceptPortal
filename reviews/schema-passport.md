# schema-passport

## Цель тура

Подробный обзор вкладки **Паспорт** концептуальной схемы (`/rsforms`, `RSTabID.CARD`): метаданные в библиотеке (название, сокращение, описание), версии, доступ, расположение/владение и боковая сводка по конституентам и корректности. Тур не автозапускается; вход через BadgeHelp на форме (`PassportTourID.SCHEMA`). Все шаги вызывают `openPassport` — гарантируют открытую вкладку паспорта.

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `tab-passport` | Слабый: якорь — вкладка «Паспорт», заголовок шага — «Паспорт схемы»; текст дублирует следующие шаги |
| `form` | explain | `passport-form` | OK с замечаниями: поля совпадают с UI; якорь покрывает всю форму (включая версии и доступ), не только три поля |
| `versions` | explain | `passport-versions` | Слабый: «Версии» vs лейбл «Версия»; «панель над ним» не совпадает с тулбаром иконок |
| `access` | explain | `passport-access` | Расхождение: три разные контролы сведены в одно предложение; «только чтение» ≠ UI «Изменение» |
| `library` | explain | `passport-library` | OK с замечаниями: заголовок секции в UI отсутствует; не названа кнопка «Открыть в библиотеке» |
| `stats` | explain | `passport-stats` | Расхождение: «тело КС», «базисные», «термы» не совпадают с лейблами панели; заголовок шага не из UI |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0 — вводит в заблуждение / расхождение с UI**

- «аксиоматическое ядро и **тело КС**» (`stats`) — в панели второй блок называется **«Тело теории»** (`tx.concept.system.body`), не «тело КС».
- «например **базисные** или константные множества» (`stats`) — в разбивке **«Аксиоматическое ядро»** типы: **«Базисное множество»**, **«Константное множество»** (`tx.cst.type.basic`, `tx.cst.type.constant`). «Базисные» — терминологически неверно и не совпадает с UI.
- «режим **«только чтение»** для редакторов» (`access`) — в UI переключатель с тултипами **«Изменение: запрещено»** / **«Изменение: разрешено»** (`tx.lib.readOnly.on/off`), не слово «только чтение».

**P1 — неясно или слабое соответствие лейблам**

- Заголовок **«Паспорт схемы»** (`overview`) vs вкладка **«Паспорт»** (`tx.lib.item.passport`) — пользователь ищет другой текст на табе.
- «описание фиксирует **предметную область**» (`form`) — плейсхолдер/хинт поля: **«Предметные источники, пояснения, примечания, комментарии разработчика»** (`tx.lib.description.hint`); описание шире, чем «предметная область».
- «создание и правка — в **панели над ним**» (`versions`) — над списком версии — **ряд иконок** (откат, создание версии, редактирование версий), не «панель»; EN корректнее: «toolbar above it».
- Заголовок шага **«Версии»** (`versions`) vs лейбл поля **«Версия»** (`tx.lib.version`).
- «видимость в библиотеке» (`access`) — в UI тултипы **«Видимость: отображать»** / **«Видимость: скрывать»**; политика доступа (Личный / Защищенный / Открытый) не названа.
- Заголовок **«Панель статистики»** (`stats`) — в UI нет такого заголовка; блоки: **«Содержание»**, **«Аксиоматическое ядро»**, **«Тело теории»**, **«Корректность»**.
- «**термы**, текстовые определения и конвенции» (`stats`) — в разбивке **«Содержание»**: **«Термины»** (`tx.lang.term.plural`), **«Текстовые определения»**, **«Конвенции»** — «термы» не совпадает с UI.

**P2 — косметика / стиль**

- «**Паспорт схемы** описывает концептуальную схему…» (`overview`) — help-термин «Паспорт схемы» (`tx.schema.passport.short`) ок для ссылки, но рядом с табом «Паспорт» звучит тяжеловато.
- Заголовок формы в UI — **«Концептуальная схема»** (`tx.schema`); в туре не упомянут.
- «Сохранение — иконка или Ctrl + S» (`form`) — кнопка **«Сохранить изменения»** (`tx.general.changes.save`); на Mac подсказка Cmd+S (в тексте только Ctrl).

## Пропущенные шаги

1. **Точка входа** — заголовок **«Концептуальная схема»** + BadgeHelp (рядом с ним стартует тур); сейчас первый шаг на табе, не на форме.
2. **Три элемента блока «Доступ»** — выпадающий список политики (Личный / Защищенный / Открытый), иконка видимости, иконка запрета изменения; шаг `access` не различает их.
3. **Действия версионирования** — «Создание версии», «Редактирование версий», «Откатить к версии» / переключение на актуальную — только обобщение «панель над ним».
4. **«Открыть в библиотеке»** — кнопка с `IconFolderOpened` (`tx.lib.location.open`); в `library` названа только правка расположения (`IconFolderEdit`).
5. **«Сбросить изменения»** — парная кнопка к сохранению (`tx.general.changes.reset`).
6. **Производная схема** (`is_produced`) — блокировка расположения/владельца и части правок; для импортированных схем это критично.
7. **Практика раскрытия статистики** — второй абзац `stats` про раскрытие категорий без `mode: 'interact'`; пользователь не пробует UI.

## Избыточные / сливаемые шаги

1. **`overview` + `form`** — `overview` перечисляет название, доступ, версии и статистику, которые раскрываются в следующих шагах; можно слить ввод в `form` («вкладка Паспорт — здесь метаданные схемы…») и убрать отдельный шаг на таб.
2. **`library` + `form`** — метаданные библиотеки визуально неразрывны с формой (одна колонка); отдельный шаг оправдан якорем, но copy «Под формой» дублирует структуру, уже видимую на шаге `form`; можно одно предложение в `form` + короткий `library`.
3. **`access`** — один абзац на три контрола; если не разбивать на подшаги, текст можно перенести в `form` без нового якоря (якорь `passport-access` тогда теряет смысл).

## Топ-3 правки copy

1. **`stats`**: заменить «тело КС» → **«Тело теории»**; «базисные или константные множества» → **«базисное и константное множество, родовая структура, аксиома»**; «термы» → **«термины»**; заголовок шага — по первой категории (**«Содержание»**) или **«Сводка по схеме»**, не «Панель статистики».
2. **`access`**: явно назвать три элемента: политика (**Личный / Защищенный / Открытый**), **видимость в списке библиотеки**, **разрешение/запрет изменения** (тултипы «Изменение: …»), не «только чтение».
3. **`versions`**: «панель над ним» → **иконки над полем «Версия»** — создание версии, редактирование списка, откат/переключение; заголовок **«Версия»** или «Версии схемы».

## Итог

Тур покрывает все основные якоря паспорта КС и заканчивается на `passport-stats` (требование реестра). Структура шагов логична, но copy в **`stats`** и **`access`** системно расходится с русскими лейблами UI; **`versions`** и **`overview`** слабо сопоставлены с видимыми элементами. Главные пробелы: не объяснены три контрола доступа, действия версионирования, кнопка «Открыть в библиотеке» и ограничения для производных схем. Шаг **`overview`** избыточен как отдельный spotlight на таб. Приоритет правок: P0 в `stats` и `access`, затем конкретизация `versions` и выравнивание «Паспорт» / «Паспорт схемы» в `overview`.
