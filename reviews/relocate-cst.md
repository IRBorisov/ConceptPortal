# relocate-cst

## Цель тура

Объяснить диалог **«Перенос конституент»** (`tx.oss.relocate`): выбор пары схем (исходная → целевая) в рамках одной ОСС, переключение направления и отметка конституент для переноса с подтверждением кнопкой **«Переместить»** (`tx.general.move`). Тур привязан к маршруту `/oss`, запускается из диалога (`tourID={DialogTourID.RELOCATE_CST}`), `autoStart: false`.

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `relocate-routing` | Частично: якорь верный (блок с двумя `SelectLibraryItem` и кнопкой направления). Текст описывает порядок действий, но не называет плейсхолдеры UI **«Исходная схема»** / **«Целевая схема»** (`tx.oss.relocate.source` / `.target`); вместо них — «исходную/целевую схему» и графовые «схема-аргумент / результат». Иконка в copy всегда ↑ (`IconRelocationUp value={true}`), хотя кнопка переключает ↑/↓. |
| `selection` | explain | `relocate-list` | Проблема: якорь на списке конституент, но шаг может показаться **до выбора целевой схемы** — тогда список пуст (`tx.list.empty` → «Список пуст»), а body говорит про отметку и подтверждение. Утверждение «в списке только конституенты без наследования» **не совпадает с поведением** `getRelocateCandidates` (при переносе вниз в списке все конституенты схемы, включая наследованные; при переносе вверх наследованные с `parent_schema === целевая` тоже попадают в список). Термин **«ребро»** и **«заблокированные остаются на месте»** в UI не отражены. |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0**

- «В списке **только конституенты без наследования**, допустимые для выбранного **ребра**» (`selection`) — фактически неверно: список строится из `getRelocateCandidates`; наследованные строки **могут отображаться** (перенос вниз — весь состав схемы; перенос вверх — наследованные, привязанные к целевой КС). Переносятся только **собственные** (`!is_inherited` в `moveTarget`), но это не то же самое, что «только в списке».
- «**заблокированные остаются на месте**» (`selection`) — в диалоге нет строк «заблокированных»; недопустимые конституенты **просто не попадают в список** (фильтр кандидатов), а не остаются видимыми и неотмеченными. Пользователь не увидит «оставшихся».
- «допустимые для выбранного **ребра**» (`selection`) — в UI нет слова «ребро»; есть плейсхолдеры **«Исходная схема»** и **«Целевая схема»**, tooltip кнопки **«Направление перемещения»** (`tx.oss.relocate.direction`). EN-аналог «chosen edge» — та же проблема.

**P1**

- «затем укажите допустимую **целевую схему**» (`overview`) — ок по смыслу, но в UI label — **«Целевая схема»** (placeholder справа); первый селект — **«Исходная схема»**, а не «исходная схема» в свободной форме. Для onboarding лучше цитировать labels дословно.
- «обычно **вверх в схему-аргумент или вниз в результат**» (`overview`) — направление верное по домену, но в выпадающих списках показаны **имена КС из библиотеки**, без подписей «аргумент»/«результат».
- «Отметьте нужные и **подтвердите**» (`selection`) — кнопка диалога называется **«Переместить»**, не «Подтвердить» / «ОК». Подсказка валидации: **«Необходимо выбрать хотя бы одну собственную конституенту»** (`tx.oss.relocate.validate`) — тур говорит «без наследования», UI — **«собственную»** (`tx.cst.original`); термины не связаны в copy.
- «Унаследованные … **остаются на месте**» (`selection`) — при пустом или урезанном списке формулировка создаёт ложное ожидание видимых неактивных строк; наследованные в списке отмечены **пунктирной рамкой** (`BadgeConstituenta`, `border-dashed`), но тур это не объясняет.
- Шаг `selection` без `onEnter`/задержки: при прохождении тура «подряд» spotlight на **пустом** списке расходится с текстом про выбор конституент.

**P2**

- «чтобы **распространение оставалось согласованным**» (`selection`) — абстрактно; в справке (`help-relocate-cst`) причины изложены конкретнее (зависимости при переносе вверх, удаление из наследников при переносе вниз).
- «переключите направление кнопкой» + только иконка ↑ (`overview`) — не показан вид **переноса вниз** (↓); нет отсылки к разным исходам «вверх» vs «вниз» из help.
- Заголовок шага `overview` **«Перенос конституент»** совпадает с `tx.oss.relocate` — OK; пункт контекстного меню ОСС, открывающий диалог, подписан **«Конституенты»** (`tx.cst.plural`) с hint «Перенос конституент…» — тур точку входа не упоминает (для dialog-tour допустимо, но новичок может не связать).

## Пропущенные шаги

- Кнопка **«Переместить»** и подсказка валидации (`tx.oss.relocate.validate`) — без них шаг `selection` обрывается на «подтвердите».
- Счётчик **«Выбраны {selected} из {total}»** (`tx.general.selection.status`) в шапке списка — единственный явный feedback выбора.
- Поиск и панель графового выделения в `PickMultiConstituenta` (строка поиска, `ToolbarGraphSelection`) — есть в UI, в туре нет (для короткого dialog-tour опционально, но при плотных схемах важно).
- Различие **перенос вверх / вниз** (наследование vs перенос собственных) — в help два подраздела; тур сводит к одному абзацу `selection`.
- Состояние **пустого списка** до выбора целевой схемы — нет подсказки «сначала выберите целевую схему» (логичный `onEnter`-guard или отдельный короткий шаг после заполнения routing).

## Избыточные / сливаемые шаги

- **`overview` + `selection`**: при двух якорях разделение оправдано; overlap — оба упоминают «конституенты без наследования / что можно перенести». Если оставить 2 шага, из `overview` убрать детали списка; если сокращать тур — слить в один шаг с якорем `relocate-routing` и коротким вторым абзацем про список (потеря отдельного spotlight на таблице).
- Повтор «между схемами, связанными операцией ОСС» (`overview`) и «допустимые для … ребра» (`selection`) — одна мысль; вторую формулировку лучше привязать к паре селектов, не к «ребру».
- Абзац про распространение в `selection` не избыточен по смыслу, но без привязки к UI воспринимается как общая теория — либо убрать, либо заменить на observable правило («в списке только …; остальные не показываются»).

## Топ-3 правки copy

1. **`selection` body**: убрать «ребро» → «для выбранной пары **Исходная схема → Целевая схема**»; заменить «только без наследования» на «переносятся **собственные** конституенты (`tx.cst.original`); наследованные в списке не выбираются / не переносятся»; убрать «заблокированные остаются на месте» → «недопустимые **не показываются в списке**».
2. **`selection`**: «подтвердите» → «нажмите **Переместить**»; при необходимости одна фраза про подсказку **«Необходимо выбрать хотя бы одну собственную конституенту»**.
3. **`overview`**: явно назвать плейсхолдеры **«Исходная схема»** и **«Целевая схема»**; для кнопки направления — «**Направление перемещения**» (↑ в аргументы / ↓ в результат) вместо только статичной иконки ↑.

## Итог

Тур минимален (2 шага `explain`), якоря `relocate-routing` и `relocate-list` соответствуют разметке в `dlg-relocate-constituents.tsx`, заголовок совпадает с диалогом. Критичные расхождения — **ложное описание состава списка** (наследованные могут быть видны), **жаргон «ребро»** без UI-аналога и **миф о «заблокированных строках»**, которых пользователь не видит. Структурная слабость — шаг `selection` при **пустом списке** и отсутствие шага про **«Переместить»** / валидацию. После правки `selection` под реальное поведение `getRelocateCandidates` и привязки copy к labels селектов тур станет согласован с интерфейсом и со справкой `help-relocate-cst`.
