# formula-tree

## Цель тура

Объяснить полноэкранный диалог дерева разбора родоструктурного выражения: как читать строку выражения и дерево, как перемещаться по канве, как обособить подвыражение в новую конституенту (диалог `DlgShowAstExtract`). Тур стартует из `BadgeHelp` внутри диалога; предполагает, что пользователь уже открыл дерево из редактора выражения.

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `ast-expression` | **Частично OK.** Якорь на баннер выражения (`dlg-show-ast-extract.tsx`, `dlg-show-flat-ast.tsx`) — уместен. Текст про подсветку фрагмента верен. Типизация показывается не в баннере, а во всплывающей подсказке у узла на канве — формулировка «а также отобразится типизация» без указания места вводит в заблуждение. |
| `canvas` | explain | `ast-canvas` | **Частично OK.** Якорь на обёртку React Flow — верно. Space / колёсико / клик для выбора соответствуют `diagram-flow` и `ASTFlow`. Легенда цветов урезана (3 роли против 6 в help) и неточна («имена конституент» ≠ бирюзовые литералы, глобальные id, радикалы). |
| `extract` | explain | — | **Критические расхождения.** Центрированный шаг без якоря: кнопка «Обособить» и панель в DOM (`PopoverExtraction`), но `data-tour` на них нет — spotlight не целит UI. RU copy «Выделить» / «выделение» / «панель выделения» не совпадает с `tx.rsexpression.extract` («Обособить»), help («обособление») и `tx.rsexpression.extract.confirm`. Шаг релевантен только для `DlgShowAstExtract`; при `DlgShowFlatAst` (ошибки, read-only, без `onCreateCst` и т.д.) текст про Q и кнопку неприменим. Не сказано, что обособление доступно только для вложенного узла **с дочерними** (`canExtract`: `parent` и `children.length > 0`). |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0**

- «нажмите <kbd>Q</kbd> или кнопку … **Выделить**» — в UI кнопка `tx('tx.rsexpression.extract')` = **«Обособить»** (`popover-extraction.tsx`). Пользователь не найдёт «Выделить».
- «**В панели выделения** заполните терм …» — в help и confirm-строках доменное слово **«обособление»** (`help-formula-tree/topic.ru.tsx`, `tx.rsexpression.extract.confirm`). Два разных термина для одной панели.

**P1**

- «Наведите на узел — фрагмент подсветится в строке сверху, **а также отобразится типизация**» — типизация в tooltip у узла дерева (`ast-node.tsx`, `buildTooltip`), не в баннере. Без «у узла» / «в подсказке» звучит так, будто тип появится в строке сверху.
- «Цвета узлов соответствуют ролям в языке (**логика, имена конституент, типизированные выражения**)» — в help перечислены 6 групп (зелёный — объявление id, бирюзовый — глобальный id, оранжевый — логика, синий — типизированные, красный — присвоение/итерация, серый — составные). Тур молчит про красный и составные; «имена конституент» не покрывает литералы и радикалы в бирюзовой группе (`colorBgSyntaxTree`).
- Шаг `extract` без якоря: кнопка и панель обособления визуально под баннером выражения, но тур не подсвечивает их — слабая связь текста с UI на финальном шаге.
- «Если **выделение** доступно» — в UI disabled-состояние кнопки без объяснения; не описаны условия (не корень, узел с дочерними, режим extract-диалога).
- «нажмите <kbd>Q</kbd>» — в коде Q **переключает** панель (`setPopoverOpen(prev => !prev)`), не только открывает; при повторном Q панель закроется без обособления.

**P2**

- Заголовок шага overview «Дерево разбора» совпадает с `tx.rsexpression.ast`; EN в туре — «Parse tree», в i18n/help — «Syntax tree» (паритет EN, не RU).
- Placeholder полей панели: «Новый термин» / «Новое текстовое определение» — тур говорит «терм» и «текстовое определение» без «новый»; смысл близкий, формулировки разные.
- FR: тур «Extraire», UI `tx.rsexpression.extract` = «Isoler» — та же класс проблемы, что RU «Выделить» vs «Обособить».

## Пропущенные шаги

1. **Якорный шаг на обособление** — `data-tour` на `PopoverExtraction` (кнопка «Обособить» / открытая панель) с `anchor` и, возможно, `placement: 'bottom'` под баннером.
2. **Условия доступности обособления** — вложенный узел (не корень), узел с дочерними подузлами; диалог extract vs view-only (`DlgShowFlatAst`).
3. **Расширенная легенда цветов** — хотя бы отсылка к help «Виды узлов» или 2–3 ключевые цвета (логика / id / ошибка с красным кольцом).
4. **Где смотреть типизацию** — отдельная короткая ремарка в overview или canvas: tooltip при наведении на узел.
5. (Опционально) Закрытие диалога — `Esc` / кнопка «Закрыть» внизу (`ModalView`); сейчас не упомянуто.

## Избыточные / сливаемые шаги

- **overview + canvas** — не сливать: первый шаг про баннер и hover, второй про выбор и навигацию канвы; логичная прогрессия.
- **Упоминание цветов в canvas** — слишком короткое, чтобы быть полноценным шагом; лучше **расширить** copy или **слить** с overview одним абзацем «виды узлов», чем оставлять трёхсловную легенду.
- **extract (2 абзаца)** — объединение в один абзац возможно, но второй абзац (терм + Ctrl+S + Esc) полезен; **не сливать** без якоря на панель — сначала добавить anchor.

## Топ-3 правки copy

1. **«Выделить» → «Обособить»** во всём шаге `extract`; «выделение» / «панель выделения» → «обособление» / «панель обособления» — выровнять с `tx.rsexpression.extract` и help.
2. **Overview:** «…фрагмент подсветится в строке сверху; **типизация — во всплывающей подсказке у узла**» (убрать иллюзию типа в баннере).
3. **Extract:** добавить одну строку условий: «Доступно для вложенного узла с подузлами (не корень); в режиме только просмотра кнопка недоступна» — перед Q / Обособить.

## Итог

Тур короткий и по структуре уместен для диалога (баннер → канва → обособление), якоря `ast-expression` и `ast-canvas` существуют и совпадают с UI. Главный провал — **RU copy шага `extract` не совпадает с лейблом кнопки «Обособить»** (P0) и расходится с help по термину «обособление». Второй блок проблем — **нет якоря на панель обособления** и **неточное описание типизации и цветов**. Перед релизом: выровнять терминологию, уточнить где показывается типизация, добавить `data-tour` на extract-UI и условия `canExtract`; при необходимости — различие extract vs view-only диалога.
