ConceptPortal Critical Design Review

Date: 2026-10-05 Baseline: main @ 1ad4a401 Scope: backend (Django/DRF), frontend (React/Vite), deployment (Docker, nginx), CI
Verdict
Design is sound and well documented. Pass with actions: one confirmed access-control bug, two production-reliability gaps, and several hardening items should be closed before the next release.
3 high 5 medium 8 low 9 strengths noted

Backend suite: 356 tests passing on SQLite; no migration drift. Details in Evidence.

System under review

ConceptPortal is an editor for RSForm conceptual schemas and operational synthesis schemas (OSS). A Django REST API on PostgreSQL serves a React SPA; a framework-free TypeScript package (@rsconcept/domain) holds the RS-language and graph logic, and rstool / rstool-mcp expose it to agents over the /api/agents API-key routes.

Findings

Ordered by severity. High means user-visible defect or a control that does not work as configured in production.

HighCDR-01

Owners lose read access to their own read-only, non-public items

rsconcept/backend/shared/permissions.py — ItemAnyone → ItemEditor → can_edit_item

ItemAnyone.has_object_permission falls back to can_edit_item for non-public items, and can_edit_item returns False as soon as read_only is set, before it checks ownership. Read access is therefore gated on write access. Verified by probe test: owner of a private + read_only item gets 403 on both GET /api/library/{id} and GET /api/rsforms/{id}/details. Editors of protected items hit the same wall.

Fix: route the read path through the existing can_read_library_item() helper instead of the edit check, and add a regression test for owner/editor × read_only × policy.

HighCDR-02

Throttles are per worker process, not per client

project/settings.py (no CACHES) · docker-compose-prod.yml (gunicorn -w 3)

No CACHES is configured, so DRF throttles use the default per-process LocMemCache. With three gunicorn workers each holds its own counters: the login limit of 5/min behaves like up to 15/min, signup 3/h like 9/h, and every counter resets on deploy or worker recycle. The careful NUM_PROXIES/X-Forwarded-For hardening is undercut by this. (The agents app is unaffected: it keeps rate state in the database.)

Fix: configure a shared cache (Redis, or DatabaseCache as a zero-infrastructure step) and add a test asserting the throttle backend is not LocMem outside DEBUG.

HighCDR-03

Cascading library deletes and creates are not atomic

apps/library/views/library.py — perform_destroy, perform_create, perform_update

perform_destroy runs OSS propagation (before_delete_schema), deletes bound RSModels, and recursively deletes owned schemas of an OSS, all outside transaction.atomic; ATOMIC_REQUESTS is off. A failure midway leaves a half-deleted OSS or schemas whose inheritance was already rewritten. perform_create likewise creates the item and then its Layout/RSModel in separate commits, and perform_update syncs operation titles after the locked block commits.

Fix: wrap each of these methods in transaction.atomic() (the rsform/oss actions already follow this pattern).

MediumCDR-04

Permission defaults fail open

apps/rsform/views/rsforms.py:83 · project/settings.py DEBUG / DEFAULT_PERMISSION_CLASSES

View-level get_permissions maps unlisted actions to Anyone, so a new @action added to RSFormViewSet becomes public unless someone remembers the list. Globally, DEFAULT_PERMISSION_CLASSES switches to AllowAny whenever DEBUG is on, and DEBUG defaults to true for runserver, shell and migrate when the env var is missing.

Fix: make the fallback branch ItemEditor (or raise), keep IsAuthenticated as the default regardless of DEBUG, and add a test that enumerates every routed action and asserts an explicit permission mapping.

MediumCDR-05

Optimistic concurrency is advisory, and custom actions check without a lock

shared/concurrency.py · frontend/src/backend/api-transport.ts

The X-Expected-Time-Update token is optional, and custom actions (create-cst, update-cst, OSS operations) only run the unlocked check in get_object; two writers can both pass it. The docstring acknowledges this. The SPA sends the token on content mutations (about half of the 80 mutating call sites), but library metadata calls such as set-owner, set-editors, set-access-policy and version updates send none, and agents/API clients can omit it.

Fix: call assert_expected_time_update_locked inside the existing atomic blocks of custom actions; consider requiring the token for session-authenticated content writes.

MediumCDR-06

CI tests a different database engine than production

.github/workflows/backend.yml

Backend CI runs on the SQLite default; production is PostgreSQL 16. select_for_update is a no-op on SQLite, so the row-lock concurrency path, JSON field behaviour and constraint semantics are never exercised before deploy. CI also does not run makemigrations --check.

Fix: add a postgres:16 service container to the backend job and a migration-drift check.

MediumCDR-07

List endpoints are unpaginated

apps/library/views/library.py · settings REST_FRAMEWORK (no DEFAULT_PAGINATION_CLASS)

No pagination class is configured anywhere. GET /api/library serialises every accessible item, and list cost grows linearly with the library. Pagination currently lives only in the client (stores/preferences.ts).

Fix: introduce cursor or limit/offset pagination on library and user lists behind a versioned contract change, synced with the frontend query hooks.

MediumCDR-08

DB_PORT is silently ignored

project/settings.py — DATABASES['default']['DB_PORT']

The database dict uses the key DB_PORT; Django reads PORT. Production works only because Postgres listens on the default 5432. Moving the database to a non-default port would break the backend while entrypoint.sh (which does use $DB_PORT) reports the DB as ready.

Fix: rename the key to PORT.

LowCDR-09

Secret files are read without stripping whitespace

project/settings.py — _get_secret

A trailing newline in secrets/*.txt becomes part of the DB password, SMTP host and user. Add .strip().

LowCDR-10

HSTS settings on the API host are inconsistent

project/settings.py — SECURE_HSTS_*

SECURE_HSTS_SECONDS=3600 is combined with PRELOAD=True; preload lists require at least one year. nginx already sends one year for the SPA host. Align the API host to 31536000 or drop the preload flag.

LowCDR-11

Long-lived sessions and PII to Sentry by default

project/settings.py

Session cookies last two years and CSRF cookies one year; SENTRY_SEND_DEFAULT_PII defaults to true, which ships user identifiers and IPs to a third party. Consider 30–90 day sessions with sliding renewal and a PII-off default.

LowCDR-12

Email uniqueness is enforced only in serializers

apps/users/serializers.py · django.contrib.auth User

Concurrent signups can create two users with the same email; login-by-email then fails for both. Add a case-insensitive unique constraint (requires a custom user model or a profile-side constraint).

LowCDR-13

Edge proxy lacks timeouts and general rate limits

nginx/production.conf

Only the Sentry tunnel is rate-limited; there are no proxy_read_timeout, connection limits or body-size caps on API routes. Already tracked in TODO.txt; listed here because it pairs with CDR-02.

LowCDR-14

Backend image built on PPAs

rsconcept/backend/Dockerfile

Python 3.12 comes from the deadsnakes PPA on ubuntu:jammy, plus the ubuntu-toolchain PPA, and static/media/backup are chmod a+rwx. An official python:3.12-slim base gives reproducible, smaller, faster-patched images; tighten the directory modes to the app user.

LowCDR-15

Every signed-in user can list all users

apps/users/views.py — ActiveUsersView

Names and IDs of all active users are returned to any authenticated account. This is presumably for the editor picker; scope it to a search with a minimum query length if the user base grows.

LowCDR-16

No Content-Security-Policy on the SPA

nginx/production.conf

Only frame-ancestors is set; the reason (inline bootstrap script, embeds, workers) is documented. Moving the inline script to a hashed or external file would allow a script-src policy and remove most of the XSS blast radius.

Strengths

  • Layering is explicit and enforced by docs: docs/architecture.md, per-package AGENTS.md, and a pure domain package with adapters that carry no business rules.
  • Mutation services are transactional: apps/rsform/mutations.py and the OSS actions wrap writes and propagation in transaction.atomic.
  • API key design is solid: 256-bit random secrets, SHA-256 at rest, public prefix lookup, revocation, DB-backed rate state and capped request logging.
  • Proxy-aware throttle identity: nginx overwrites X-Forwarded-For and NUM_PROXIES is documented next to it.
  • Fail-closed production settings: missing SECRET_KEY or ALLOWED_HOSTS raises when DEBUG is off; secure cookies follow DEBUG.
  • Robust client transport: lazy CSRF bootstrap with one retry, abort handling, cross-tab reset notifications, zod validation at the boundary.
  • Optimistic concurrency exists end to end (header, 409 response, client token), which most apps of this size lack; CDR-05 is about tightening it.
  • Test breadth: backend unit and view tests, domain/front unit tests, and Playwright E2E running in CI.
  • No password-reset enumeration and scoped throttles on login, signup, reset, OSS clone and cctext.

Recommended actions

  1. Before next release: fix CDR-01 with a permission-matrix test; configure a shared cache (CDR-02); wrap library create/update/destroy in transactions (CDR-03); rename DB_PORT → PORT (CDR-08).
  2. Next sprint: run backend CI on PostgreSQL with a migration-drift check (CDR-06); make permission fallbacks fail closed (CDR-04); add locked concurrency checks to custom actions (CDR-05).
  3. Planned: server-side pagination (CDR-07); nginx timeouts and limits (CDR-13); slimmer backend image (CDR-14); session lifetime, PII and HSTS tidy-up (CDR-10, CDR-11).

Evidence and method

  • Static reading of settings, URL routing, permissions, concurrency helpers, library/rsform/oss views, agent authentication, user views, Dockerfile, compose files, nginx config and CI workflows.
  • CDR-01 confirmed with a throwaway Django test (owner, private, read_only=True): both endpoints returned 403. The probe was removed afterwards.
  • Backend suite: manage.py test on SQLite: 356 tests, all passing. makemigrations --check: no drift today.
  • Not covered in depth: the OSS propagation engine's algorithmic correctness, the RS-language parser in @rsconcept/domain, and frontend rendering performance.
