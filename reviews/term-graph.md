# term-graph

## Цель тура

Познакомить с вкладкой **Граф** редактора (песочница / схема / модель): левая панель вида и фильтров, панель правки, список скрытых узлов, верхняя панель режимов и выделения, взаимодействие с холстом. Единственная практика — переключение подписей узлов (`interact` + `GRAPH_LABELS_TOGGLED`).

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `tab-graph` | OK по смыслу; якорь на вкладке с подписью UI «Граф» (`tx.graph`), а заголовок шага — «Граф термов» (`tx.termGraph`) — расхождение с подписью вкладки. |
| `options` | interact (`interactionRegion`: `graph-toggle-labels`) | `graph-options` | Перегружен: якорь охватывает всю левую колонку (правка, счётчик выделения, раскраска, скрытые, кнопки), а текст — только про вид/фильтры; interact корректен (кнопка подписей + emit). |
| `edit` | explain | `graph-edit` | Частично дублирует `options`; якорь — узкая полоса над левой панелью; кнопки видны только при `isContentEditable` — оговорка в тексте есть, но шаг всё равно показывается в read-only. |
| `hidden` | explain | `graph-hidden` | OK по якорю; текст верный по сути, но заголовок списка в UI — «Скрытые [N из M]», не просто «список скрытых». |
| `tools` | explain | `graph-tools` | Якорь на верхней панели по центру — верно, но шаг идёт **после** левой колонки, хотя панель визуально сверху с первого кадра; часть описанного (режим, тип связи при рисовании, «кнопки» влияющих/зависимых) скрыта или в выпадающем меню. |
| `canvas` | explain | `graph-canvas` | OK как финал; хоткеи панорамирования верны (`Space`/`WASD` в `DiagramFlow` + `useContinuousPan`), но есть неточности по удалению и формулировкам. |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0**

- «`<IconClustering />` (`V`) скрывает порождённые узлы» — в `toolbar-tg-options.tsx` в подсказке кнопки указан `V`, но в `use-handle-actions.ts` переключение порождённых — **`KeyB`**; `KeyV` открывает быстрое редактирование. Пользователь, следующий туру, не получит ожидаемого действия.
- «Кнопки выделяют связанные узлы — например `<IconGraphCollapse />` все влияющие и `<IconGraphExpand />` все зависимые» — в UI это **пункты выпадающего меню** «Выделить на основе выбранных…» (`tx.graph.select.expand`), а не отдельные кнопки на панели; при пустом выделении меню недоступно — текст создаёт ложное ожидание.

**P1**

- Заголовок шага overview: «Граф термов» vs подпись вкладки в UI: «Граф» (`tx.graph`). Ссылка на справку (`tx.termGraph` = «Граф термов») — норма, но пользователь ищет вкладку по другому слову.
- «`<IconFilter />` открывает настройки расположения узлов и фильтров» — подсказка кнопки: «Настройки отображения» (`tx.general.view.settings`); про «расположение узлов» в tooltip нет.
- «`<IconGraphMode />` Просмотр … `<IconGraphMode />` Редактор» — фактические подсказки: «Режим: Просмотр» / «Режим: Редактор» (`tx.termGraph.mode.*`); переключатель режима **не показывается**, если редактирование запрещено (`toolbar-schema-graph.tsx`).
- «`<IconEdgeType />` атрибутирование / определение» в шаге `tools` — это переключатель **типа создаваемой связи** в режиме «Редактор»; отдельно в левой панели есть селект фильтра «Связь: …» (`SelectEdgeType`) — в `options` сказано «типы связей» без различения «фильтр отображения» vs «тип при рисовании».
- «двойной щелчок открывает редактор конституенты» (`hidden`, `canvas`) — грамматика и термин: в EN — «concept editor»; формулировка звучит обрывисто («редактор конституенты» вместо «редактор выбранной конституенты» / «редактирование конституенты»).
- Шаг `options`: «Слева — раскраска узлов и типы связей» — селект типов связей (`SelectEdgeType`) рендерится только для атрибутивных схем (`schema.is_attributive`); для части контекстов тура блок отсутствует.

**P2**

- «`<IconFitImage />` вписывает граф в экран» — в UI есть хоткей **`G`** (`prepareTooltip(tx.flow.fitView, 'G')`), в тексте тура не упомянут (в `oss-graph` аналог указан).
- «`<IconGraphMode />` … `<IconEdgeType />`» — хоткеи **`Q`** / **`E`** есть в tooltips, в туре отсутствуют.
- «`<kbd>Delete</kbd> удаляет выбранные конституенты» — в коде также срабатывает **Backquote** (`\``).
- «`<IconCrucial />` (`F`) переключает статус «ключевая»» — в UI: «Переключить статус ключевой» (`tx.cst.crucial.toggle`); кавычки вокруг «ключевая» избыточны.
- «`<IconTypeGraph />` открывает граф ступеней для выделения» — tooltip кнопки: «Граф ступеней выделенных конституент» (`tx.typeGraph.fromSelected`); кнопка доступна и при пустом выделении (берёт все конституенты).
- «`<IconFocus />` фокусирует одну конституенту» — tooltip: «Сфокусировать конституенту (ПКМ по узлу)»; альтернативный жест не упомянут.
- Шаг `edit` не упоминает кнопку быстрого редактирования (`IconEdit2`, `V` / в tooltip «Alt + V») — присутствует в той же панели `graph-edit`.

## Пропущенные шаги

- Верхняя панель (`graph-tools`) **раньше** по расположению, чем по порядку шагов — нет раннего шага «где вы режим и выделение» до погружения в левую колонку.
- Панель выделения: сброс (`Esc`), «Выделить группу…» (ядро / ключевые / собственные / наследованные), «Максимизация», инверсия — в `tools` лишь намёк на влияющих/зависимых.
- Счётчик «Выделено N из M» (`tx.general.selection.status`) между `graph-edit` и раскраской.
- Режим фокуса: метка фокус-конституенты, сброс, ограничения (часть кнопок левой панели disabled при `focusCst`).
- Диалог «Настройки отображения» (параметры графа) — единственный явный «фильтр» из текста `options`.
- Скрытие изолированных узлов (`KeyH`, `tx.graph.node.isolated.hide`) — отдельная кнопка/фильтр, не покрыта.
- Селектор ОСС в `graph-edit` (если у схемы есть OSS) — не упомянут.
- Ограничения read-only: в `tools` и `edit` не сказано, что значительная часть панели просто скрыта.

## Избыточные / сливаемые шаги

- **`options` + `edit` + `hidden`** — три шага на одну левую колонку (`graph-edit` и `graph-hidden` вложены в `graph-options`); spotlight `options` уже подсвечивает правку и скрытые до их шагов. Имеет смысл: один шаг «Левая панель» с подпунктами или разнести якоря так, чтобы не перекрываться.
- **`tools` (вторая половина) + `canvas`** — выделение на холсте и клавиши `Esc`/`Delete` логично объединить с `canvas`; блок про режимы оставить в `tools`.
- **`options` (первый абзац) + `tools`** — «типы связей» в `options` (фильтр) и «атрибутирование/определение» в `tools` (рисование) лучше явно развести в одном шаге или cross-link, иначе дублирование термина «связь».

## Топ-3 правки copy

1. **Исправить хоткей порождённых узлов:** заменить «(`V`) скрывает порождённые узлы» на **`B`** (и синхронизировать tooltip кнопки в UI — вне scope тура, но copy тура должен соответствовать реальному поведению).
2. **Переписать блок про влияющих/зависимых:** «В меню „Выделить на основе выбранных…“ — пункты „Влияющие“ и „Зависимые“» вместо «кнопки … все влияющие и все зависимые».
3. **Согласовать вход в тур с вкладкой:** в `overview` указать «вкладка **Граф**» и пояснить, что в справке она называется «граф термов»; либо унифицировать заголовок шага с `tx.graph`.

## Итог

Тур v3 покрывает основные зоны интерфейса и содержит одну рабочую interact-практику (подписи), но страдает от **пространственного порядка шагов** (верхняя панель — в конце), **перекрывающихся якорей** левой колонки и **критической ошибки хоткея V/B**. Текст местами не совпадает с подписями UI (фильтр, режимы, выпадающее выделение) и не различает фильтр отображения связей и тип связи при рисовании. Для минимального выигрыша: исправить P0, упростить левую колонку до 1–2 шагов, поднять `tools` выше или слить с `overview`/`canvas`, добавить оговорку read-only.
