# structure-planner

## Цель тура

Короткий гид по полноэкранному диалогу раскрытия структуры типизации конституенты: граф операций (проекции, множество-сумма) и верхняя панель для просмотра/редактирования формального определения, имени (сокращения) и терма выбранного узла с сохранением или созданием конституенты. Тур запускается из диалога (`BadgeHelp` + `tourID`), не объясняет вход («Раскрыть структуру» / «Порождение структуры») — это в `concept-editor` и help-топике.

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `structure-planner-graph` | OK по якорю (`StructureFlow`, полный canvas). Замечания: copy не описывает, что на узлах видно; название «Планировщик структуры» ≠ UI/help («Раскрытие структуры»); «сумма множеств» ≠ help «множество-сумма». |
| `panel` | explain | `structure-planner-panel` | Частично OK: якорь на верхнюю панель (`definition` + alias + `RefsInput` + кнопки). Проблемы: «обозначение» вместо имя/сокращение; «имя новой» путает alias и терм; сброс описан шире, чем работает в UI; нет цветов узлов, read-only, диалога несохранённых при смене узла. `placement: bottom` у панели вверху экрана — допустимо, но popover уходит в граф. |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0 — «Планировщик структуры» vs видимые подписи продукта**  
Цитата (title + link): «Планировщик структуры».  
В UI: кнопка входа `tx.concept.expandStructure` — «Раскрыть структуру»; help/BadgeHelp `tx.concept.expandStructure.noun` — «Раскрытие структуры»; в `concept-editor` тур — «раскрытие структуры». В chrome диалога заголовка нет (`ModalView` fullScreen, `noFooterButton`). Пользователь не находит «планировщик» ни в кнопке, ни в справке.

**P0 — «обозначение» вместо имя / сокращение (alias)**  
Цитата: «его обозначение (зелёным — если новое)».  
В UI средняя колонка — `alias` (`selectedCst?.alias ?? inferAlias(...)`), зелёный класс `text-constructive` только для нового узла. В i18n: `tx.lib.alias.short` — «Имя», `tx.lib.alias` — «Сокращение»; на панели label нет, но доменный alias ≠ «обозначение». EN copy верно: «alias»; RU расходится с EN и терминологией Portal.

**P1 — «предлагается имя новой» смешивает alias и терм**  
Цитата: «для пустых — предлагается имя новой».  
Для узла без конституенты: alias автогенерируется и показывается зелёным в средней колонке; поле терма пустое, placeholder `tx.lang.term.validate.empty` — «Термин отсутствует». Имя новой конституенты (alias) не вводится в поле терма — пользователь вводит терм. Формулировка вводит в заблуждение.

**P1 — сброс: текст шире поведения UI**  
Цитата: «[IconReset] отменяет несохранённые правки».  
В коде `MiniButton` Reset: `disabled={!isDirty \|\| !selectedCst}` — сброс только для **существующей** конституенты с изменённым термом. Для нового узла (нет `existing`) кнопка неактивна; очистить черновик терма можно только вручную.

**P1 — граф: не объяснено содержимое и цвета узлов**  
Цитата overview: «Щёлкните узел, чтобы работать с этим структурным элементом».  
На узле: круг с alias; подпись — `term_resolved` или `labelType(type)`. Цвета: корень — фиолетовый, есть конституента — зелёный, нет — оранжевый (`colorSPNode`). Тур молчит — пользователь не связывает цвет с «уже есть / нужно создать».

**P1 — «открытой конституенты» не всегда верно**  
Цитата: «типизации открытой конституенты».  
При `spawner_path` диалог открывается на `spawner`, корень — структура основания порождённой конституенты (help: «если конституента порождённая, то корень — структура основания»). «Открытая» звучит как текущая строка редактора, не spawner.

**P1 — «сумма множеств» vs принятый термин**  
Цитата: «проекции, сумма множеств и т.д.».  
Help `topic.ru`: «множество-сумма». Порядок слов и термин не совпадают с справкой и доменным языком.

**P1 — read-only режим**  
Цитата panel п.2: «При редактировании … сохраняет».  
При `!isMutable` блок с `IconSave`/`IconNewItem`/`IconReset` скрыт, `RefsInput` disabled. Первый абзац panel не говорит, что панель может быть только для просмотра.

**P2 — подписи кнопок не названы**  
Тур: иконки save/create/reset. Tooltip в UI: `tx.general.changes.save` («Сохранить изменения»), `tx.cst.create` («Создание конституенты»), `tx.general.changes.reset` («Сбросить изменения»). Для новичка иконки без слов слабее, чем в sibling-турах с явным «Сохранить».

**P2 — «поле терма со ссылками»**  
Близко к help «текстовые отсылки» и EN «text-reference support» — приемлемо; точнее «текстовые отсылки» как в справке.

**P2 — placement шага `panel`**  
Панель `absolute top-0` по центру; `placement: bottom` — карточка тура под панелью, может перекрывать граф. Не ломает тур, но хуже, чем `top` для верхнего UI.

**P2 — EN/RU parity**  
EN overview/panel согласованы между собой; RU отстаёт по alias/terminology (обозначение, планировщик). FR копирует EN («planificateur», «alias»).

## Пропущенные шаги

1. **Содержимое узла графа** — alias в круге, подпись терма/типа, цвета (корень / есть конституента / черновик).
2. **Подписи рёбер** — `PrN` / `prN` / `red` на связях проекций (хотя бы одна фраза в overview).
3. **Несохранённые правки при смене узла** — `promptUnsaved` при `isDirty` и клике другого узла / закрытии диалога.
4. **Разделение alias vs терм** — зелёное имя в колонке vs ввод терма; создание конституенты с автоматическим alias.
5. **Подтверждение омонима** — `tx.concept.homonym.confirm` при создании с совпадающим термом.
6. **Навигация по графу** — zoom колёсиком, fit view (как минимум в духе `formula-tree` / `term-graph`); сейчас только клик.
7. **Практический `interact`** — «выберите оранжевый узел», «введите терм и сохраните» с `completeAction` (в туре нет ни одного interact-шага).
8. **Контекст входа** (опционально для slim) — откуда открыт диалог; в `concept-editor` уже есть кнопка «Раскрыть структуру».

## Избыточные / сливаемые шаги

1. **Только два шага** — избыточности мало; скорее недостаток покрытия, чем лишние шаги.
2. **`overview` + `panel`** — логичная последовательность (граф → детали выбора); сливать не стоит: разные якоря и фокус.
3. **Дублирование с help `UI_STRUCTURE_PLANNER`** — panel повторяет справку (определение, терм, Ctrl+S) без добавления цветов узлов и ограничений Reset; после расширения overview panel можно ужать до отличий тура (save/create, сброс, hotkey).
4. **Перекрёстное дублирование с `concept-editor` tools** — там уже «Раскрыть структуру» и смысл «добавить порождённые конституенты»; этот тур должен углублять UI диалога, а не повторять мотивацию — сейчас overview частично дублирует одно предложение без углубления.

## Топ-3 правки copy

1. **Выравнивание названия с UI** — title/link «Раскрытие структуры» (как `tx.concept.expandStructure.noun` и help), убрать «Планировщик структуры» из пользовательского copy.
2. **Шаг `panel`, первый абзац** — заменить «обозначение» на «имя (сокращение)»; уточнить: для нового узла имя назначается автоматически (зелёным), в поле терма вводится термин; для существующей подставляется сохранённый терм.
3. **Шаг `overview`** — добавить одну фразу про узлы (alias, подпись, цвет: фиолетовый корень / зелёный — есть конституента / оранжевый — создать); «множество-сумма» вместо «сумма множеств»; при необходимости уточнить корень для порождённых конституент.

## Итог

Тур технически корректен: два шага, якоря `structure-planner-graph` и `structure-planner-panel` есть в `dlg-structure-planner.tsx`, route `EDITOR_TOUR_ROUTES`, `autoStart: false`. Критичные проблемы copy — **P0: чужое имя «Планировщик структуры»** и **«обозначение» вместо имя/сокращение (alias)**; EN эталоннее RU. Главные пробелы по UX: **цвета и подписи узлов**, **путаница alias vs терм**, **неточное описание Reset**, **нет смены узла с несохранёнными правками**. Тур очень slim (2 explain-шага) по сравнению с `formula-tree` (3) и богатством диалога; расширение overview + правка panel даст больше, чем добавление шагов ради количества. Термин «базисное множество» в туре не фигурирует — ок для этого UI. Приоритет правок: название → alias/терм → узлы графа → Reset/read-only.
