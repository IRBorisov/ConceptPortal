# model-value

## Цель тура

Показать вкладку **Данные** (`RSModelTabID.VALUE_EDIT`): ввод, просмотр и вычисление **значений конституент** модели (Sandbox и библиотечные модели). Три шага: обзор вкладки → панель инструментов → форма редактора значения. Тур не `autoStart`; доступен из `BadgeHelp` на `toolbar-value-tab` и как subtour из `sandbox-intro` (шаг `data`).

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `tab-data` | **Якорь OK.** **Минус по лейблу:** на вкладке видно **«Данные»** (`tx.general.data`), а заголовок тура — **«Данные модели»** (`tx.model.data` / help). Текст ссылкой на help корректен по смыслу, но не совпадает с коротким таб-лейблом. Не объясняет выбор конституенты в списке слева. |
| `tools` | explain | `model-value-tools` | **Якорь OK** для панели Save / Reset / Recalculate / Calculate / Create / Clone / Delete. **Критический минус copy:** импорт/экспорт с `IconUpload` / `IconDownload` **отсутствуют на этой панели** — они в `ValuePrimaryActions` внутри формы (текстовые кнопки «Импорт» / «Экспорт»). Порядок иконок в тексте (сначала одна конституента, потом вся модель) **обратен** порядку на панели (сначала `IconCalculateAll`, потом `IconCalculateOne`). |
| `form` | explain | `model-value-form` | **Якорь OK**, охватывает форму целиком (включая `ValuePrimaryActions`, поля конституенты, `EditorRSExpression`, `ValueInput`). **Минусы:** статус описан как `IconStatusUnknown`, в UI — `IconEvalStatus` (разные иконки по состоянию); подсказка кнопки — **«Сохранить и вычислить»**, не просто «вычисление»; импорт/экспорт и диалог значения в copy шага `tools`, а не здесь, хотя якорь как раз на форме. |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0 — вводит в заблуждение, расхождение с UI**

- «<IconUpload /> / <IconDownload /> — **импорт или экспорт**» (шаг `tools`) — на подсвеченной панели `model-value-tools` **нет** этих иконок и действий. Импорт/экорт — текстовые кнопки **«Импорт»** / **«Экспорт»** (`tx.general.import` / `tx.general.export`) в верхней части формы (`ValuePrimaryActions`), с выпадающими пунктами буфера и JSON.
- «Кнопка <IconStatusUnknown /> **статуса** запускает вычисление» (шаг `form`) — в `ValueInput` используется **полоса статуса** с `IconEvalStatus` и текстом состояния (`labelEvalStatus`: «Не вычислено», «Есть данные» и т.д.), а не фиксированная иконка «неизвестно». `IconStatusUnknown` показывается только в состоянии `NOT_PROCESSED`.

**P1 — ясность / слабое совпадение с лейблами**

- Заголовок **«Данные модели»** vs таб **«Данные»** — пользователь ищет на вкладке слово «модели», его нет.
- «<IconCalculateOne /> (**Ctrl + Q**) вычисляет текущую конституенту» — на macOS в подсказках UI **Cmd + Q** (`toolbar-value-tab`, help). Тур и EN/FR copy пишут только `Ctrl`.
- **Конфликт Ctrl + Q с туром `concept-editor` и с той же вкладкой:** на вкладке «Концепт» `Ctrl + Q` — **проверка формального определения**; на «Данные» при фокусе **вне** редактора выражения — **вычисление значения конституенты** (`tab-value.tsx`). Если фокус в `EditorRSExpression` на вкладке «Данные» (для выводимых конституент), `Ctrl + Q` снова запускает **проверку выражения** (`rs-input.tsx`), а не вычисление значения — тур этого не предупреждает.
- «<IconSave /> (**Ctrl + S**) **сохраняет значение**» — сохраняет **все несохранённые поля формы** (термин, определения, значение), не только значение.
- «<IconCalculateAll /> (**Alt + Q**) пересчитывает всю модель» — hotkey работает на вкладке (`tab-value.tsx`), но **подсказка кнопки** на `model-value-tools` **не показывает** `Alt + Q` (в отличие от панелей списка модели и вкладки «Расчет»).
- Подсказка кнопки статуса в UI: **«Сохранить и вычислить»** (`tx.rsexpression.saveAndCalculate`) — тур говорит только «запускает вычисление», не упоминая сохранение перед расчётом.
- Кнопка «Вычислить конституенту» на панели **неактивна при несохранённых изменениях** (`isModified`) — в copy не сказано.

**P2 — полнота / дубли**

- «Неопределяемым понятиям задают интерпретацию (для базисных множеств — элементы предметной области)» — терминологически верно, но плотно для onboarding; диалог привязки упомянут только в `form`.
- Не упомянуты: **сброс** (`IconReset`), **создание / клон / удаление** конституент на панели, **список конституент** слева (`ConstituentsNarrowPicker`), кнопки **«Редактирование значения»** / **«Просмотр значения»**, **очистка**, **случайные значения**, переключатель класса значения.
- Шаг `tools` и шаг `form` **дублируют** тему вычисления (панель vs статус в форме) без разграничения сценариев.
- `Alt + Q` и пересчёт модели **дублируют** туры `model-evaluator`, `constituents-list`, teaser в `sandbox-intro` — норма для shared editor tours, но избыточно при последовательном прохождении.

## Пропущенные шаги

| Что | Почему важно | Приоритет |
|-----|--------------|-----------|
| **Выбор конституенты** в узком списке / боковой панели | Без выбора форма пуста; основной сценарий вкладки | P1 — лучше в `overview`, не отдельный шаг (нет якоря) |
| **Импорт / экспорт значения** (`ValuePrimaryActions`) | Сейчас ошибочно приписаны панели `tools`; реально в форме | P0 — правка `tools` + дополнение `form`, не новый шаг |
| **Диалог базовой интерпретации** vs **диалог редактирования значения** | Для базисных множеств и структур — разные входы (`showEditBinding` / `showEditValue`) | P1 — расширить `form` |
| **Два статуса** на одной форме (выражение + значение) для выводимых конституент | Путаница с `concept-editor` и с hotkey `Ctrl + Q` | P1 — одно предложение в `form` |
| Отличие от вкладки **«Расчет»** | Обе вкладки: пересчёт, статус, просмотр значения — разный смысл | P1 — в `overview` (симметрично review `model-evaluator`) |
| **Сброс изменений** на панели | Видимая кнопка рядом с «Сохранить» | P2 |

Отдельный шаг под список конституент **не рекомендуется** без нового `data-tour` на `ConstituentsNarrowPicker`.

## Избыточные / сливаемые шаги

| Шаг | Вердикт |
|-----|---------|
| `overview` | **Оставить.** Нужен при запуске с `BadgeHelp` и как entry subtour из `sandbox-intro`. |
| `tools` | **Оставить**, но **убрать из copy** импорт/экспорт и сократить дублирование с `form`. Альтернатива: **слить с `overview`** (2 шага: вкладка+панель в одном, `form` отдельно) — потеря фокуса на панели. |
| `form` | **Оставить** — основной сценарий. Не дробить без новых якорей. |
| Вычисление в `tools` + статус в `form` | **Частичное дублирование.** Имеет смысл: в `tools` — панельные кнопки и hotkeys; в `form` — статус-бар и диалог интерпретации. Явно развести формулировками, иначе **слить абзац про Ctrl+Q** в один шаг. |

## Топ-3 правки copy

1. **`tools` — импорт/экспорт:** удалить строку с `IconUpload` / `IconDownload`; перенести в `form`: «Кнопки **Импорт** и **Экспорт** загружают или выгружают значение текущей конституенты (буфер обмена или JSON)».
2. **`form` — статус и вычисление:** заменить «Кнопка … статуса запускает вычисление» на «Нажмите полосу статуса (**Не вычислено** / …) — **«Сохранить и вычислить»**»; убрать жёсткую привязку к `IconStatusUnknown`; для выводимых конституент добавить: «Если фокус в поле формального определения, **Ctrl+Q** проверяет выражение, а не значение».
3. **`overview` + `tools` — лейблы и hotkeys:** «Вкладка **Данные** (в меню — *данные модели*)»; hotkeys с веткой **Cmd** на macOS; порядок иконок как на панели (сначала пересчёт всей модели, затем одной конституенты).

Дополнительно: **`overview`** — одно предложение об отличии от **«Расчет»** (здесь редактируют значения конституент, там — произвольные выражения без изменения модели).

## Итог

Тур **технически корректен**: якоря существуют, `onEnter` открывает вкладку значений, структура зеркалит `model-evaluator`. **Критичные проблемы — шаг `tools`:** импорт/экспорт описаны элементами, которых на подсвеченной панели нет; **шаг `form`:** неверная иконка и лейбл статуса, не отражена подсказка «Сохранить и вычислить». **Стратегические риски:** расхождение «Данные» / «Данные модели», **двойной смысл Ctrl+Q** (вкладка «Концепт», редактор выражения на «Данные», вычисление значения). После правки copy (без новых шагов) тур достаточен для базового onboarding; выбор конституенты и расширенные действия формы остаются пробелами P1–P2.
