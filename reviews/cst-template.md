# cst-template

## Цель тура

Объяснить трёхвкладочный диалог «Создание конституенты из шаблона» (`tx.cst.template.instantiate`): выбор шаблона из банка выражений, подстановка аргументов в текущую схему, правка полей основной конституенты и пакетное создание с зависимостями из банка.

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain (default) | `cst-template-tabs` | **OK с оговоркой** — подсветка только полосы вкладок; названия вкладок совпадают с UI (Шаблон / Аргументы / Редактор). Заголовок шага «Создание по шаблону» ≠ заголовок диалога «Создание конституенты из шаблона». |
| `workflow` | explain | `cst-template-body` | **Слабо** — текст про две вкладки (Шаблон + Аргументы), но диалог открывается на вкладке «Шаблон» и тур не переключает вкладки; подсветка всего `Tabs`, пользователь видит только содержимое первой вкладки. Нет `onEnter` и нет якорей на контролы «Источник»/«Категория», таблицу аргументов, «Итоговое определение». |
| `create` | explain | `cst-template-tabs` | **Проблема** — повторный якорь `cst-template-tabs` (как у `overview`); текст про вкладку «Редактор» и кнопку «Создать», но подсветка снова только на вкладках, форма редактора и футер с «Создать» вне зоны. Пользователь, скорее всего, всё ещё на «Шаблон». |

**Повторяющиеся якоря:** `cst-template-tabs` — шаги `overview` и `create` (2 из 3). Второй якорь `cst-template-body` — только `workflow`. Других `data-tour` в диалоге нет.

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0 — несовпадение с подписями полей на вкладке «Редактор»**

- «поправьте **обозначение**, **терм** и **определения**» (`create`) — в форме: **Имя** (`tx.lib.alias.short`), **Термин** (`tx.lang.term`), **Формальное определение** / **Текстовое определение** (`tx.lib.defineFormal`, `tx.lib.defineText`). Слово «обозначение» в UI нигде не встречается; «определения» во мн. ч. не указывает, какое поле править.

**P0 — шаг про «Редактор» без переключения вкладки**

- «На вкладке **Редактор** поправьте…» (`create`) — при старте тура активна вкладка «Шаблон» (`TabID.TEMPLATE`); механизма переключения вкладок диалога в туре нет (`onEnter`/`changeTab` работает только с вкладками страницы, не диалога).

**P1 — заголовок шага vs заголовок диалога**

- Заголовок шага: «**Создание по шаблону**» (`overview`) vs заголовок модалки: «**Создание конституенты из шаблона**» (`tx.cst.template.instantiate`).

**P1 — шаг `workflow` описывает невидимое**

- «На вкладке **Аргументах** привяжите каждый параметр…» — при шаге `workflow` пользователь по умолчанию смотрит вкладку «Шаблон»; таблица аргументов, пикер конституент под ней и блок «Итоговое определение» не показаны и не подсвечены.

**P1 — действие «Создать» не привязано к UI**

- «**Создание** добавляет все нужные вспомогательные функции…» (`create`) — кнопка в футере называется «**Создать**» (`tx.general.create`); якоря на футер/кнопку нет, в тексте слово «Создание» не совпадает с меткой кнопки.

**P1 — не упомянуты видимые контролы вкладки «Шаблон»**

- На вкладке есть «**Источник**» и «**Категория**» (`tx.cst.template.source`, `tx.cst.template.category`), список шаблонов и превью «Выбор шаблона выражения» — в туре не объясняется, откуда берётся список и зачем фильтр категории.

**P2 — терминология**

- «**терм**» (`create`) vs подпись поля «**Термин**».
- «**параметризованное понятие или утверждение**» (`workflow`) — в пикере отображаются `term_raw` / `definition_raw` без явных типов; формулировка верная по смыслу, но не совпадает с тем, что видит пользователь в списке.
- «**вспомогательные функции из банка**» (`workflow`, `create`) — доменно уместно, но в UI нет такой подписи; связь с банком выражений только через ссылку в `overview`.

**P2 — EN-расхождение (для паритета, не RU)**

- EN-тур: третья вкладка «**Constituent**» (`content.en.tsx`), UI: «**Editor**» (`tx.general.role.editor`). RU и FR совпадают с UI («Редактор» / «Éditeur»).

## Пропущенные шаги

1. **Источник и категория** — выбор банка (текущая схема / библиотека) и фильтрация списка шаблонов.
2. **Выбор шаблона** — клик по элементу в `PickConstituenta`, превью термина и формального выражения внизу вкладки.
3. **Привязка аргументов** — таблица (Имя / Значение / Типизация), выбор строки, пикер конституент схемы, сброс значения.
4. **Итоговое определение** — поле предпросмотра на вкладке «Аргументы» (`tx.cst.template.result`), куда подставляется результат.
5. **Вкладка «Редактор»** — поля формы, переключатель типа, «ключевая» конституента; отдельный якорь на панель или форму.
6. **Кнопка «Создать» и валидация** — `validationHint` («Выберите шаблон…», дубликат имени и т.д.) и условия `canSubmit`.

## Избыточные / сливаемые шаги

- **`overview` + `create`** — оба на `cst-template-tabs`; визуально почти одна и та же подсветка в начале и в конце. Имеет смысл **слить** в один вводный шаг (маршрут вкладок + финальное «Создать») **или** развести якоря: `overview` — вкладки, `create` — тело вкладки «Редактор» + футер (потребуются новые `data-tour`).
- **`workflow`** — сжимает две вкладки в один шаг при одном якоре; при добавлении переключения вкладок логично **разделить** на «Шаблон» и «Аргументы» либо оставить один шаг, но с явным указанием «перейдите на вкладку Аргументы» и якорем на контент второй вкладки.

## Топ-3 правки copy

1. **`create` — выровнять с подписями формы:** заменить «обозначение, терм и определения» на «**Имя**, **Термин**, **формальное** и **текстовое определение**» (как в `FormCreateCst`).
2. **`overview` — заголовок:** «Создание по шаблону» → «**Создание конституенты из шаблона**» (как `tx.cst.template.instantiate`) или явная отсылка к заголовку диалога в первом предложении.
3. **`create` — привязка к кнопке:** «Создание добавляет…» → «Нажмите **Создать**: в схему добавятся…»; параллельно — переключение на вкладку «Редактор» (инженерно: новый якорь/`onEnter`, иначе текст остаётся вне контекста).

## Итог

Тур короткий (3 шага, все `explain`), даёт верную схему «Шаблон → Аргументы → Редактор», но **слабо синхронизирован с тем, что пользователь видит**: нет переключения вкладок диалога, два шага делят один якорь на полосе вкладок, шаг `create` описывает форму и действие «Создать» вне подсветки. Критичны расхождения copy с подписями полей (**обозначение** vs **Имя**) и описание вкладки «Редактор» при открытой по умолчанию «Шаблон». Для приемлемого onboarding нужны якоря на контент вкладок/кнопку «Создать» и правки терминологии; без этого тур остаётся обзорным абзацем, а не пошаговым сопровождением диалога.
