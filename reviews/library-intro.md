# library-intro

## Цель тура

Кратко познакомить с экраном «Библиотека»: проводник папок слева, строка текущего пути, панель поиска/фильтров и таблица элементов. Тур объяснительный (`explain`), без практических шагов; стартует вручную с `/library` (BadgeHelp на `library-location`). Версия 2, 5 шагов.

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `welcome` | explain | — | OK: рамка и охват тура совпадают с UI. |
| `folders` | explain | `library-folders` | OK якорь; текст неполный (нет разворота дерева, админ-группировки `/U`). |
| `location` | explain | `library-location` | Частично: якорь верный, но кнопка «редактирование» описана неверно; подсказки UI не совпадают с формулировкой тура. |
| `search` | explain | `library-search` | Проблемный: расхождение метки режима поиска с видимым лейблом селектора; неточные названия фильтров; не упомянут «Искать в». |
| `table` | explain | `library-table` | Частично: открытие/цвета/сортировка в зоне якоря; экспорт (`IconDownload`) вне подсветки — в `ExportDropdown` над таблицей, не в `library-table`. |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

### P0

1. **Метка режима контекстного поиска не совпадает с UI-селектором.**  
   Тур: «Режим «Метаданные» (🔍) и «Контекстный поиск» (📝) переключаются переключателем режима».  
   UI: в `selector-search-mode.tsx` карта `items` для выбранного значения `context` берёт `tx.lib.contents` → **«Содержание»**; в выпадающем списке пункт — `tx.lib.search.mode.context` → **«Контекстный поиск»**. Пользователь видит в закрытом селекторе «Содержание», а тур называет режим «Контекстный поиск». Справка (`help-library/topic.ru.tsx`) и тур согласованы между собой, но оба расходятся с триггером селектора — это баг UI (`context: tx('tx.lib.contents')` вместо `tx.lib.search.mode.context`), а не только копирайта тура.

2. **Кнопка с `IconFolderEdit` — не «переименование папки».**  
   Тур: «кнопка ✏️ переименовывает папку (если доступно)».  
   UI: `aria-label` = «Редактирование расположения», `title` = «Редактирование пути / Перемещаются только Ваши схемы…»; диалог `dlg-change-location` с заголовком «Редактирование расположения» и кнопкой «Переместить». Это смена пути/перемещение схем в дереве, не rename папки в проводнике.

### P1

3. **«Фильтры по типу» — неточная метка элемента.**  
   Тур: «Фильтры по типу сужают список до схем, моделей или ОСС».  
   UI: селектор `SelectorLibraryFilter` — это общий **«Фильтр»** (`tx.general.filter`) с пунктами «Я владелец», «Я редактор», «Скрытые», «Схема», «ОСС», «Модель». Тип — лишь часть опций; формулировка вводит в заблуждение.

4. **«фильтр по владельцу» ≠ лейбл контрола.**  
   Тур: «при необходимости — фильтр по владельцу».  
   UI: `SelectUser` с `placeholder`/`aria-label` = **«Поиск по владельцу»** (`tx.lib.search.byOwner`).

5. **Экспорт упомянут в шаге `table`, но не попадает в подсветку.**  
   Тур: «экспорт видимой таблицы — ⬇️».  
   UI: `ExportDropdown` в той же строке, что `ToolbarSearch` (`library-page.tsx`), класс `hidden sm:block`, якорь `library-search` / `library-table` его не охватывает. На шаге `table` кнопка экспорта не в spotlight.

6. **Подсказка сброса фильтров.**  
   Тур: «сбрасывает пользовательские фильтры».  
   UI: `title` кнопки = **«Сбросить фильтр»** (`tx.general.filter.reset`, ед. число).

### P2

7. **Кнопка вложенных папок — другая формулировка.**  
   Тур: «включает или скрывает элементы из вложенных папок».  
   UI: tooltip **«Вложенные папки: Вкл» / «Вложенные папки: Выкл»**, `aria-label` = «Отображение вложенных папок». Иконка `IconShowSubfolders` (обёртка над `IconSubfolders`) — визуально совпадает с иконкой в туре.

8. **Дублирование иконки `IconText`.**  
   В режиме «Содержание»/контекста в тулбаре две кнопки с `IconText`: пункт селектора режима и `PopoverContextFields` («Искать в»). Тур привязывает `IconText` только к переключателю режима — при активном контекстном поиске неясно, о какой кнопке речь.

9. **Заголовок шага `location`.**  
   Тур: «Текущее расположение». UI не показывает такой заголовок; ближайший термин каталога — «Расположение» (`tx.lib.location`). Некритично, но нет якорного лейбла.

10. **Мобильная вёрстка.**  
    `SelectorSearchMode`, `PopoverContextFields`, `SelectUser`, `ExportDropdown` скрыты на `max-sm`. Тур не предупреждает, что часть описанных контролов на узком экране недоступна.

11. **EN-копирайт (побочно):** «Ctrl/Cmd-click a folder copies» — грамматическая ошибка; RU-версия корректна.

## Пропущенные шаги

- **`PopoverContextFields`** («Искать в» / «Искать везде») — единственный способ сузить поля контекстного поиска; есть в справке, в туре отсутствует.
- **Экспорт** (`ExportDropdown`: CSV/JSON/PDF) — упомянут в тексте `table`, но без якоря и вне зоны подсветки; логичен отдельный подпункт в `search` или расширение якоря.
- **Разворот/сворачивание веток** в проводнике (клик по иконке папки) — есть в справке, нет в `folders`.
- **Пагинация таблицы** (10/20/30/50/100) — заметный контрол внизу `DataTable`.
- **Админ-режим**: группировка личных папок `/U` по владельцу и синхронизация с «Поиск по владельцу» — нетипичный, но важный сценарий для staff.
- **Пустое состояние таблицы** (ссылки «Создать схему» / «Сбросить фильтр») — полезно для онбординга новых пользователей.

## Избыточные / сливаемые шаги

- **`welcome`** — можно сократить до одного абзаца или слить с `folders`, если нужен тур на 4 шага; сам по себе не избыточен как вступление.
- **`search`** — перегружен: типовой фильтр, режим поиска, владелец, сброс — при этом «Искать в» вынесен за скобки. Имеет смысл либо разбить (фильтры / режим поиска), либо убрать второстепенное («фильтр по владельцу») в пользу контекстных полей.
- **`table`** — экспорт логичнее убрать из этого шага (или перенести в `search`/отдельный якорь), оставив открытие, сортировку и цветовую кодировку.
- **`folders` + `location`** — разные зоны UI, сливать не стоит; связь «выбор папки → путь в breadcrumb» можно одной фразой в `location`.

## Топ-3 правки copy

1. **Режим поиска:** в `search` назвать режим так, как его видит пользователь в селекторе — **«Содержание»** (или сначала починить `selector-search-mode.tsx`, затем оставить «Контекстный поиск» с пояснением в скобках). Сейчас тур ссылается на лейбл из выпадающего списка, а не из триггера.
2. **`location`, кнопка `IconFolderEdit`:** заменить «переименовывает папку» на **«редактирует путь расположения / перемещает ваши схемы в папке»** — в духе `tx.lib.location.edit` и подсказки кнопки.
3. **`search`, фильтры:** «Фильтры по типу…» → **«Селектор «Фильтр» сужает список (тип, роль, скрытые…)»**; «фильтр по владельцу» → **«Поиск по владельцу»** — дословно как в UI.

## Итог

Тур покрывает основные зоны библиотеки и якоря в целом верны, но шаг `search` расходится с реальным UI из‑за бага метки «Содержание» vs «Контекстный поиск», а шаг `location` неверно описывает действие кнопки редактирования пути. Шаг `table` обещает экспорт вне зоны подсветки. Для онбординга критично выровнять copy с `tx.*` лейблами, исправить (или явно отразить в туре) баг селектора режима и добавить «Искать в» для контекстного поиска. Оценка готовности: **требует правок copy и, вероятно, фикса UI-селектора** перед показом новым пользователям.
