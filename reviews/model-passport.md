# model-passport

## Цель тура

Подробный гид по вкладке «Паспорт» концептуальной модели (`/models`): что описывает паспорт, как править название/сокращение/описание, настроить доступ, перейти к связанной схеме, увидеть метаданные библиотеки и прочитать боковую панель статистики. Уникально для модели по сравнению с `schema-passport` / `oss-passport`: шаг `schema` (ссылка на исходную КС). Не покрывает: остальные вкладки редактора (Список, Концепт, Граф, Данные, Вычисление), меню модели, индикаторы проблем на вкладках.

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P1 — шаг `overview`: «Паспорт модели» vs вкладка «Паспорт»**  
Цитата (title): «Паспорт модели»; в body ссылка «Паспорт модели».  
В UI вкладка: «Паспорт» (`tx.lib.item.passport`); заголовок формы: «Концептуальная модель» (`tx.model`). «Паспорт модели» есть в help (`tx.model.passport`), но не на вкладке — пользователь ищет несуществующую подпись на табе.

**P1 — шаг `stats`: структура панели не совпадает с текстом**  
Цитата: «Боковая панель совмещает счётчики структуры схемы с проблемами модели…».  
В UI четыре раскрываемые категории: «Содержание», «Схема», «Корректность», «Модель». Текст не называет «Корректность» (омонимы, дубликаты, ошибки разбора схемы) и «Содержание»; сводит схемную структуру и схемные проблемы в одну фразу «структура схемы».

**P1 — шаг `access`: «блок доступа» vs расположение в UI**  
Цитата: «Блок доступа задаёт политику доступа, видимость в библиотеке и режим «только чтение»…».  
В UI — горизонтальная панель в строке сокращения: label «Доступ» + селектор политики + кнопки «Видимость: отображать/скрывать» и «Изменение: запрещено/разрешено». Слово «блок» и шаг после всей формы создают ожидание отдельной секции ниже описания.

**P1 — шаг `access`: «только чтение для этой модели»**  
Цитата: «…режим «только чтение» для этой модели».  
В `schema-passport` точнее: «…для редакторов». В UI read-only ограничивает редактирование (иконки `IconImmutable` / `IconMutable`); формулировка «для модели» не объясняет, кого именно затрагивает запрет.

**P2 — шаг `form`: «Сохранение» без текста кнопки**  
Цитата: «Сохранение — [IconSave] или Ctrl + S».  
Кнопка в UI: «Сохранить изменения»; на Mac подсказка — Cmd + S. Иконка без слова «Сохранить» — слабее, чем могло бы быть.

**P2 — шаг `form`: поле «Название»**  
Текст перечисляет «название, сокращение, описание» — «Сокращение» и «Описание» с label, «Название» только placeholder/aria-label без видимого label (как в sibling-турах).

**P2 — шаг `stats`: неполный перечень строк блока «Модель»**  
Перечислены: неопределяемые без интерпретации, нарушенные аксиомы, неверные данные, ошибки вычисления — совпадают с основными строками UI. Не упомянуты: «Пустое значение терма», «Мощность базы» / «Базис» (видимые в раскрытии «Модель»).

**P2 — шаг `schema`: только иконка в тексте**  
Цитата: «Ссылка [IconRSForm] открывает исходную концептуальную схему…».  
На экране — сокращение схемы (alias) с иконкой; без подсказки пользователь может не связать кликабельную строку с «ссылкой» из тура.

**P2 — шаг `library`: без привязки к иконкам**  
Цитата: «Под формой — расположение в библиотеке, владелец, редакторы и даты…».  
Верно по смыслу; в UI все поля кликабельны (папка, смена расположения, владелец, редакторы) — тур не намекает на действия, в отличие от `schema-passport` library.

**P2 — порядок шагов vs визуальная компоновка**  
На широком экране панель `passport-stats` видна с первого шага паспорта (колонка справа), объяснение — только в конце. Не ошибка, но ранние шаги оставляют «немую» статистику.

## Пропущенные шаги

1. **Четыре категории статистики** — минимум имена «Содержание», «Схема», «Корректность», «Модель» в шаге `stats` (как рекомендовано для `sandbox-passport`).
2. **Заголовок формы «Концептуальная модель»** и `BadgeHelp` на форме (точка входа в тур) — не упомянуты.
3. **Подписи контролов доступа** — политика (Личный / Защищенный / Открытый), переключатели видимости и read-only по отдельности.
4. **Кнопка «Сбросить изменения»** — видна при правках, в туре нет (допустимо для explain-тура).
5. **Индикаторы проблем на вкладках** (`tx.schema.issue.plural` / `tx.model.issue.plural` на `TabList`) — связь статистики с навигацией по проблемам.
6. **Практический шаг `interact`** — сохранить модель или раскрыть категорию статистики (ни одного `mode: 'interact'`).

## Избыточные / сливаемые шаги

1. **`form` + `access`** — `passport-access` вложен в `passport-form`; шаг `form` подсвечивает доступ до отдельного шага `access`. Имеет смысл слить: в `form` — поля и Ctrl+S; в том же или следующем абзаце — строка «Доступ» справа от сокращения.
2. **`form` + `schema`** — `passport-schema-link` тоже внутри формы; отдельный шаг оправдан навигацией к КС, но при слиянии тур сократится с 6 до 5 шагов без потери якоря (ссылку можно выделить вторым абзацем в `form` или оставить отдельным — якорь уникален для модели).
3. **`overview`** — при запуске с `BadgeHelp` на уже открытом паспорте шаг на вкладке частично дублирует контекст; можно укоротить body до отличий модели от схемы (привязка к КС + модельная статистика).

## Топ-3 правки copy

1. **`stats` body** — назвать четыре блока UI; разделить: «Содержание» и «Схема» — структура КС; «Корректность» — проблемы схемы; «Модель» — перечисленные модельные проблемы (добавить «пустое значение терма» при желании полноты).
2. **`overview` title/body** — title «Паспорт» (как вкладка) или «Вкладка „Паспорт“»; в body: «паспорт концептуальной модели» без несуществующего label «Паспорт модели» на табе; можно сослаться на help «Паспорт модели» явно.
3. **`access` body** — убрать «блок»; указать расположение «в строке сокращения, справа»; три элемента: политика доступа, видимость в библиотеке, запрет изменений для редакторов (как в `schema-passport`).

## Итог

Тур технически корректен: шесть шагов, все якоря есть в UI модели (`form-rsmodel`, `toolbar-item-access`, `editor-library-item`, `view-model-stats`), `onEnter` стабильно открывает паспорт, финал на `passport-stats` по registry. Терминология домена в порядке («неопределяемые без интерпретации» = UI). Главные пробелы: **несовпадение title/overview с label вкладки «Паспорт»**, **упрощённое описание статистики** без четырёх видимых категорий и без блока «Корректность», **неточное описание доступа** (расположение и смысл read-only). Критичных P0 (битый anchor, неверный route, ложный термин) нет. Шаг `schema` — ценное отличие от `oss-passport`, оставлять. Приоритет правок: `stats` → `overview` → `access`; слияние `access` в `form` — опционально для сокращения перекрытия якорей.
