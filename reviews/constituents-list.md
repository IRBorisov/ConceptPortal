# constituents-list

## Цель тура

Пошагово показать вкладку **Список** (`tab-list`): что такое конституенты в таблице, текстовый поиск, счётчик выбора, панель действий и жесты в таблице (выделение, открытие, перестановка). Тур общий для Песочницы, схемы (`/rsforms`) и модели (`/models`); единственный практический шаг — ввод в поиск (`mode: interact`, `completeAction: constituents-list.search-used`).

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain (default) | `tab-list` | **OK с оговорками** — якорь совпадает с вкладкой «Список»; ссылка помощи жёстко на `UI_MODEL_LIST` (неверно на схеме). |
| `filter` | interact | `list-search` | **OK с оговорками** — якорь и `completeAction` согласованы с `SearchBar` + emit на Enter/blur при непустом запросе; id шага `filter` вводит в заблуждение (только текстовый поиск, без селектора фильтра). |
| `selection` | explain | `list-selection` | **OK с оговорками** — якорь есть только при `isContentEditable`; текст «выделение» расходится с UI «Выбраны … из …». |
| `toolbar` | explain | `list-toolbar` | **Частично** — якорь только в режиме редактирования; порядок и состав иконок в copy не совпадают с реальной панелью; нет кнопки сброса (ESC). |
| `interact` | explain | `list-table` | **Критично для модели** — жесты верны, но «открывает в редакторе» неверно для `/models` (переход на вкладку «Данные»); для схемы вкладка называется «Понятие», не «редактор». |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0**

- **P0** — `interact`: «Двойной щелчок или щелчок с Alt открывает конституенту в редакторе» — в модели `TabModelList` вызывает `gotoActiveValue` → вкладка **«Данные»** (`RSModelTabID.VALUE_EDIT`), не «Редактор конституенты» / «Понятие». Тур обязан быть контекстно-нейтральным (`editor-tours.ts`), формулировка ложна для половины маршрутов.
- **P0** — `overview`: ссылка «список» → `HelpTopic.UI_MODEL_LIST` всегда; на схеме корректен `UI_SCHEMA_LIST`. Аналогично `filter`: «руководстве по списку конституент» → `UI_SCHEMA_LIST` — на модели должно быть `UI_MODEL_LIST`.

**P1**

- **P1** — `interact`: ссылка «редакторе» → `UI_SCHEMA_EDITOR` («Редактор конституенты») не совпадает с подписью вкладки в UI: `tx.concept` = **«Понятие»** (`rsform-tabs.tsx`, `model-tabs.tsx`). Пользователь после двойного щелчка видит вкладку «Понятие», а не «Редактор».
- **P1** — `toolbar`: перечислены только «создать / клонировать / удалить / вверх-вниз / ключевые», но в UI слева есть **сброс выделения** (`IconReset`, tooltip «Сбросить выделение», `ESC`) — в `selection` упомянут только `Esc`, кнопка на панели не названа. В модели первой после сброса идёт **«Пересчитать модель»** (`Alt + Q`) — в copy она в конце абзаца, не в порядке панели.
- **P1** — `toolbar`: не упомянуто меню **создания по типу** (`IconOpenList`, `tx.cst.create.clean`) — отдельный вход рядом с `IconNewItem`; на узком экране `IconNewItem` скрыт (`hidden xs:block`), остаётся только меню.
- **P1** — `selection` + `toolbar`: якоря `list-selection` и `list-toolbar` рендерятся только при `isContentEditable`; в read-only шаги дадут `anchor.unavailable` или пустую подсветку — тур не предупреждает.
- **P1** — `filter`: «Список отфильтруется по имени, термину, определениям и конвенции» — поиск также идёт по **формальному** определению (`definition_formal`, колонка «Формальное определение») и **текстовому** (`definition_resolved`/`definition_raw`); слово «определениям» без уточнения не сопоставимо с двумя колонками таблицы.

**P2**

- **P2** — `overview`: заголовок «Список конституент» vs вкладка **«Список»** (`tx.list`) — допустимо, но в теле лучше явно «вкладка Список».
- **P2** — `selection`: заголовок «Счётчик выделения» vs UI `tx.general.selection.status` = **«Выбраны {selected} из {total}»** — нет слова «счётчик»; термин «выделение» vs «выбраны».
- **P2** — `filter`: id шага `filter`, заголовок «Поиск» — на вкладке списка нет `SelectorCstFilter` (он в боковой панели `ConstituentsSearch`); пользователь может искать отдельный выпадающий фильтр.
- **P2** — `filter`: «Нажмите Enter или щёлкните вне поля — гид продолжится» — `completeAction` срабатывает только при **непустом** `trim()`; пробелы не продвигают (кнопка «Далее» всё же доступна).
- **P2** — `interact`: «Перетаскивайте строки» дублирует `toolbar` (стрелки вверх/вниз); оба шага описывают перестановку.
- **P2** — `overview`: «статус вычисления» — колонка в модели подписана **«Значение»** (`tx.rslang.value.short`), не «статус»; без привязки к заголовку колонки.
- **P2** — EN parity: в `content.en.tsx` для поиска — «alias», в RU — «имени»; оба соответствуют колонке «Имя» (`tx.lib.alias.short`).

## Пропущенные шаги

1. **Колонка «Значение» в модели** — единственное отличие таблицы модели от схемы; в `overview` одна фраза, без якоря на `BadgeEvaluation` / колонку `value`.
2. **Экспорт списка** — `ExportDropdown` (`tx.general.export`) справа над таблицей (`sm+`), без `data-tour`.
3. **Меню создания по типу конституенты** (`IconOpenList` + dropdown `CstType`) — реальный путь создания, не только `IconNewItem`.
4. **Кнопка сброса выделения на панели** (`IconReset`) — дополняет `Esc` из шага `selection`.
5. **Read-only / просмотр чужой схемы** — нет шага или дисклеймера, что панель и счётчик недоступны.
6. *(Вне вкладки списка)* селектор фильтра (`SelectorCstFilter`: ключевые, базовые, ошибки схемы/модели) живёт в `ConstituentsSearch` на других экранах — не ошибка тура, но пользователь может ожидать его здесь после шага `filter`.

## Избыточные / сливаемые шаги

| Пара | Рекомендация |
|------|----------------|
| `toolbar` (стрелки ↑↓) + `interact` (drag-and-drop) | Слить в один блок про порядок: «стрелки, drag, при поиске отключено» — оставить в `interact` или `toolbar`, не в обоих. |
| `selection` (клик по строке, Esc) + начало `interact` (Shift+клик) | Объединить в один шаг «Выделение в таблице»: одиночный / Shift / Esc / сброс на панели. |
| `overview` + повтор типов конституент в `sandbox-intro` | Не дублировать в этом туре длинный перечень типов, если тур запускают из BadgeHelp на списке — достаточно «таблица конституент схемы (и значений в модели)». |

Порядок **selection → toolbar → interact** не совпадает с визуальной иерархией (панель сверху, счётчик в строке поиска) — не блокер, но **toolbar** логичнее сразу после `overview` или после `filter`.

## Топ-3 правки copy

1. **`interact` — контекстно-нейтральное открытие строки:** заменить «в редакторе» на ветвление или нейтральную формулировку, напр.: «в схеме — вкладка **Понятие**; в модели — вкладка **Данные**»; ссылки помощи — `UI_SCHEMA_EDITOR` / `UI_MODEL_VALUE` (или без ссылки, с именами вкладок из `tx.concept` / `tx.general.data`).
2. **`overview` + `filter` — согласовать HelpTopic с маршрутом:** нейтральный текст без жёсткой ссылки или две формулировки; убрать перекрёст (overview → model help, filter → schema help).
3. **`filter` — уточнить поля поиска под колонки таблицы:** «имя, термин, формальное и текстовое определение, конвенция / комментарий»; переименовать id шага в `search` (структурно, при bump `version`).

## Итог

Тур покрывает основные зоны вкладки «Список» и корректно привязывает практику поиска к `list-search` и `CONSTITUENTS_SEARCH_USED`. Критический разрыв — шаг `interact` и перекрёстные ссылки помощи: copy написан под схему, тогда как тур обязан работать и в модели (другая вкладка при открытии строки, другой мануал). Второй слой — расхождение с подписями UI («Понятие» vs «редактор», «Выбраны» vs «выделение», порядок иконок панели). Рекомендуется: исправить P0/P1 в `content.{ru,en,fr}`, слить дубли перестановки/выделения, при необходимости добавить короткий шаг про колонку «Значение» в модели; bump `version` при смене порядка шагов.
