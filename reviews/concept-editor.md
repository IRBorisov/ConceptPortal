# concept-editor

## Цель тура

Подробный обзор вкладки редактирования одной конституенты на `/sandbox`, `/rsforms` и `/models`: переключение конституенты, поля формы, проверка формального выражения и иконки панели выражения. Тур не `autoStart`; вход через `BadgeHelp` и как subtour из `sandbox-intro` (шаг `concept`). `onEnter` (`openConceptEditor`) открывает вкладку «Понятие» и при необходимости выбирает конституенту, у которой монтируется редактор выражения (`resolveExpressionEditorTarget`).

## Шаги (key | mode | anchor | вердикт)

| key | mode | anchor | вердикт |
|-----|------|--------|---------|
| `overview` | explain | `tab-concept` | **Слабый:** якорь — вкладка **«Понятие»** (`tx.concept`), заголовок и текст — **«Редактор конституенты»** (`tx.cst.edit.ui`). Содержание в целом верное; дублирует teaser в `sandbox-intro`. |
| `fields` | explain | `concept-form` | **OK по якорю** (вся форма). **Минусы copy:** перечислены только термин и формальное определение; в UI также **«Типизация»**, текстовое определение / конвенция; лейбл поля выражения зависит от типа (не всегда «Формальное определение»). |
| `check` | explain | `concept-check` | **OK по якорю** (пилюля статуса). **Минусы:** абстрактный «индикатор статуса» vs видимый текст **«не проверено»**; якорь **не монтируется** для пустых базисных/константных множеств без формального выражения. |
| `tools` | explain | `concept-tools` | **Расхождение якоря и copy:** spotlight на **панель иконок** редактора выражения (help, клавиатура, граф, дерево), но третий абзац про **«Раскрыть структуру»** — кнопка на якоре `concept-structure` в `ConstituentaPrimaryActions`, не в `concept-tools`. Для логических конституент кнопка графа скрыта — текст всё равно упоминает граф. |

## Проблемы текста и ясности UI (цитаты RU, P0/P1/P2)

**P0 — вводит в заблуждение / расхождение с UI**

- Заголовок **«Редактор конституенты»** (`overview`) vs лейбл вкладки **«Понятие»** (`tx.concept`) — пользователь смотрит на таб и не находит название из тура.
- «кнопка … **Раскрыть структуру** открывает раскрытие структуры» (`tools`) — spotlight на **другую** зону (`concept-tools`: иконки справа у поля выражения). Кнопка **«Раскрыть структуру»** (`tx.concept.expandStructure`) — текстовая кнопка над полями (`data-tour='concept-structure'`), визуально не в выделенной области.
- Шаги `check` / `tools` при выбранной конституенте типа **базисное/константное множество** с пустым `definition_formal` — якорь не появляется, карточка: **«Элемент для этого шага недоступен на странице.»** (`tx.onboarding.anchor.unavailable`). `resolveExpressionEditorTarget` переключает только если в схеме есть другая подходящая конституента; для схем только X#/C# без выражений тур ломается на 3–4 шагах.

**P1 — неясно или слабое соответствие лейблам**

- «Редактируйте **термин и формальное определение**» (`fields`) — в форме видны также **«Типизация»** (`tx.rslang.typification`) над полем выражения; для производных — **«Текстовое определение»**; для неопределяемых — **«Конвенция»** (в `overview` перечислены, в `fields` — нет).
- Лейбл поля выражения не универсален: для родовой структуры (демо S1 в песочнице) — **«Область определения»** (`tx.lib.defineFormal.structure`), не «Формальное определение».
- «**Граф ступеней**» (`tools`, help-ссылка) vs подсказка иконки в UI — **«Структура типизации выражения»** (`tx.typeGraph.fromExpression`). Help `UI_TYPE_GRAPH` в мануале схемы: «графа ступеней типизации» — ближе к туру, но не к тултипу кнопки.
- «индикатор **статуса выражения**» (`check`) — на пилюле текст статуса, напр. **«не проверено»** (`tx.parse.status.unknown`, в UI lowercase). Тултип кнопки: **«Проверить выражение»** (`tx.rsexpression.analyze`).
- «статус **«корректно»**» (`check`) — совпадает с **«Корректно»** (`tx.parse.status.verified`) — OK; но зелёный статус также для **«Неразмерное»** (`tx.parse.status.property`) — тур не упоминает.
- «**Дерево разбора**» (`tools`) — совпадает с `tx.rsexpression.ast` и тултипом иконки — OK.

**P2 — косметика / полнота**

- «Сохранение — **Ctrl + S**» (`fields`) — работает через `useRegisterUnsavedSave`; на Mac — Cmd+S (в тексте только Ctrl); в UI сохранение через общий механизм несохранённых изменений, без отдельной кнопки «Сохранить» на форме конституенты.
- «Нажмите на него или **Ctrl + Q**» (`check`) — тултип пилюли учитывает **Cmd + Q** на Mac; в copy только Ctrl.
- Не упомянута **символьная клавиатура** (`tx.rsexpression.keyboard`) — иконка в `concept-tools`, есть в help схемы.
- Не упомянуты **переименование**, пилюли **ядра** / **класса значения**, ссылка **«Редактирование словоформ»** у термина.
- Для логических конституент (аксиома, утверждение) иконка графа типов скрыта (`hideTypeGraph`) — абзац про граф в `tools` вводит в заблуждение.
- «Если у конституенты есть структура типизации» (`tools`) — кнопка «Раскрыть структуру» зависит от `canProduceStructure`, не от «наличия структуры» в общем смысле; для части типов кнопка не показывается.

## Пропущенные шаги

| Что | Почему важно | Приоритет |
|-----|--------------|-----------|
| **«Раскрыть структуру»** (`concept-structure`) | Якорь уже в UI; copy в `tools` описывает кнопку вне spotlight | P0 — отдельный шаг или перенос copy |
| Поле **«Типизация»** | Всегда видно для не-номинальных; между термином и выражением | P1 — расширить `fields`, не новый шаг |
| **Текстовое определение** / **«Конвенция»** | Ключевой контент; в `overview`, но не в `fields` | P1 — в `fields` |
| Subtour **formula-tree** / **structure-planner** | Диалог-туры зарегистрированы; `sandbox-intro` обещает «проверка, синтаксические инструменты и раскрытие структуры» через «Подробнее», но в `concept-editor` нет `subtour` | P2 |
| Практика **проверки** (`mode: interact`, Ctrl+Q) | Сейчас только explain; пользователь не пробует пилюлю | P2 |
| **Номинальные** конституенты — блок **«Атрибуты конституенты»** | Отдельная ветка формы | P2 |

## Избыточные / сливаемые шаги

| Шаг | Вердикт |
|-----|---------|
| `overview` | **Частично избыточен** с `sandbox-intro` → `concept` (почти тот же абзац). При прямом запуске с `BadgeHelp` нужен. Можно сократить до «вкладка **Понятие** — редактирование одной конституенты» и убрать дублирование списка полей, перенестённое в `fields`. |
| `fields` | **Оставить.** Не дробить на отдельные якоря без новых `data-tour` на поля. |
| `check` + `tools` | **Оставить раздельно** — разные якоря и сценарии. Не сливать: разная геометрия (пилюля по центру vs иконки справа). |
| `tools` (третий абзац про структуру) | **Избыточен в этом якоре** — вынести в шаг на `concept-structure` или убрать из `tools`. |
| `overview` + `fields` | Пересечение: оба перечисляют, что редактируется. **Слить перечисление полей** в `fields`, в `overview` оставить навигацию (вкладка + список слева). |

## Топ-3 правки copy

1. **`overview` — выровнять с табом:** заголовок **«Понятие»** (как `tx.concept`) + пояснение «здесь редактируется одна конституента (редактор конституенты)»; help-ссылку оставить на `tx.cst.edit.ui`.
2. **`tools` — разделить spotlight и текст:** убрать абзац про **«Раскрыть структуру»** из шага на `concept-tools`; добавить шаг `structure` с якорем `concept-structure` **или** перенести абзац туда. В `tools` оставить только иконки панели; для графа — «**Структура типизации выражения**» (как тултип) или «граф ступеней типизации» (как в help).
3. **`fields` — полнота и лейблы:** «Редактируйте **термин**, **типизацию**, **формальное выражение** (лейбл поля зависит от типа: формальное определение, область определения, определение функции…), при необходимости **текстовое определение** или **конвенцию**»; сохранение — Ctrl+S / Cmd+S.

Дополнительно (четвёртая): **`check`** — «пилюля **«не проверено»** (синяя) — нажмите или Ctrl+Q / Cmd+Q для **проверки выражения**» вместо абстрактного «индикатора статуса».

## Итог

Тур покрывает основной happy path (песочница S1: структура с выражением) и логично разбит на вкладку → форму → проверку → инструменты. **Критичные проблемы:** расхождение **«Понятие» / «Редактор конституенты»** на первом шаге; **якорь `concept-tools` не соответствует** тексту про «Раскрыть структуру»; **падение якорей** на пустых X#/C# без альтернативной конституенты. **Стратегические пробелы:** поле типизации и текстовые поля в `fields`, subtour на диалоги дерева/структуры. После выравнивания copy и шага `concept-structure` тур достаточен для базового onboarding; символьная клавиатура, пилюли и номинальные атрибуты — P2 или help.
