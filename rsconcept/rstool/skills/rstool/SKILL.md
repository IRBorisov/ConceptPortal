# rstool — маршрутизатор

Цель работы — КС, которая **отвечает запросу пользователя**. Чистые диагностики — необходимое, но не достаточное условие. Метод — `<rstool>/docs/METHOD.md`.

`<rstool>` — корень пакета: `rsconcept/rstool/` в workspace Portal, `node_modules/@rsconcept/rstool/` в npm-проекте. Все пути ниже — от него. Скиллы этапов читай по пути, когда маршрут до них дошёл; заранее не открывай.

## 1. Выбери сценарий

| Запрос                                          | Маршрут (скиллы по порядку)                                                                                                                                                                                   |
| :---------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Новая КС по тексту, ТЗ, описанию объекта        | `rs-scope` → `rs-core` → `rs-explicate` ⇄ `rs-interpret` → `rs-review` (самопроверка) → экспорт / `rs-portal`                                                                                                 |
| Развить существующую КС (файл, сессия, Portal)  | (`rs-portal`: чтение) → `rs-scope` (восстановить бриф + новые требования) → `rs-core`: новый аспект или уточнение? → `rs-explicate` → `rs-interpret` (старые сценарии — регрессия) → `rs-review` → публикация |
| Оценить / отревьюить КС                         | загрузка → `rs-scope` (восстановить задачу и бриф) → `rs-review`; `rs-interpret` — для подтверждения находок                                                                                                  |
| Починить формулу, разобрать диагностики         | `rs-explicate` с лёгким брифом: смысл фиксируется до правки. Если смысл приходится менять — `rs-core` и запись решения                                                                                        |
| Объяснить формулу или конструкцию человеку      | `rs-explain` (без брифа)                                                                                                                                                                                      |
| Требований больше, чем на одну микротеорию; ОСС | `rs-scope` → `rs-core` (деление) → `rs-synthesis`                                                                                                                                                             |
| Вопрос по синтаксису ЯРЭ                        | `docs/SYNTAX.md` (без брифа)                                                                                                                                                                                  |
| Как вызвать rstool (библиотека, stdio, MCP)     | `rstool-runtime`                                                                                                                                                                                              |

Скилл этапа: `<rstool>/skills/<имя>/SKILL.md`. Запуск rstool и скриптов — `<rstool>/skills/rstool-runtime/SKILL.md`; ссылки и REST Portal — `<rstool>/skills/rs-portal/SKILL.md`.

## 2. Держи бриф

Бриф — `brief.json` в папке задачи рядом с сессией: постановка, требования к выразительным средствам, различения, инварианты, журнал решений, сценарии. Формат — `docs/BRIEF.md`. Для точечной правки достаточно лёгкого брифа (одно требование, один сценарий).

После любого шага проверь готовность:

```bash
npx tsx <rstool>/skills/scripts/check-brief.ts --session <abs>/session.json --brief <abs>/brief.json
```

(в workspace Portal: `pnpm --filter @rsconcept/rstool exec tsx skills/scripts/check-brief.ts …`). Вывод называет **этап**, блокеры и **следующий шаг** — иди туда. Этапы: `scope` → `rs-scope`, `core` → `rs-core`, `explicate` → `rs-explicate`, `interpret` → `rs-interpret`, `review` → `rs-review`.

## 3. Общие правила

**Пользователь — предметник, ты — методник.** До формализации задай вопросы раунда 1 (`rs-scope`), после гипотезы ядра — раунда 2 (`rs-core`). У каждого вопроса — твой предложенный ответ. «Продолжайте» или «на ваше усмотрение» закрывает только уже заданные вопросы, а не следующий раунд. Если спросить нельзя — запиши допущения, статус брифа `assumed`, и скажи об этом в отчёте.

**Смысл важнее «зелёного».** Ради чистых диагностик нельзя:

- удалять или ослаблять аксиому, связанную с инвариантом брифа, без нового решения в журнале;
- превращать производное понятие (`D#`/`F#`/`P#`) в `S#`, `X#` или `C#`;
- заменять формулу тривиальной (`∅`, `D5 := X1`, тавтология);
- удалять конституенту, на которую ссылается бриф, или оставлять непустой `failed` после `best_effort`;
- оставлять пустую конвенцию у неопределяемого понятия.

Не получается выразить смысл — вернись к ядру или запиши `openQuestions` и честно скажи «готово частично».

**Границы правок.** Задача по КС не означает правку `<rstool>`. Скрипты, сессии, бриф и экспорт — в папке задачи (каталог пользователя, `.tmp/`), не в пакете. Пакет правь только по явной просьбе.

**Язык ответа.** Пиши терминами предметной области, а не именами API: «формальное определение», «конституента», «диагностики», «правка схемы», а не `definitionFormal`, `applySchemaPatch`. Имена конституент (`X1`, `D3`) и формулы ЯРЭ приводи как есть, лучше с термином: «терм `D3` (просроченные выдачи)». Словарь API → текст — `skills/rstool-runtime/SKILL.md`.

**Термины КС** — только из `docs/DOMAIN.md`, раздел «Термины: не путать». Никогда «базис» / «базисы»: для `X#` — **базисное множество**, для слоя `X#`/`C#`/`S#` — **неопределяемые понятия**. `T#` — высказывание, не «теорема». `R#` — радикал, не конституента. Буквы из учебника (`D` для родовой структуры, `T` для терма) не используй.

## 4. Отчёт пользователю

Шаблон — в `rs-review`. Минимум для любой сборки или правки:

1. Как схема отвечает на запрос: таблица «требование → конституента → сценарий».
2. Что сознательно не выражено (ограничения и невыразимое), допущения, открытые вопросы.
3. Решения по ядру, которые пользователь должен знать.
4. Диагностики и результат проверки брифа; файлы (сессия, бриф, экспорт).
