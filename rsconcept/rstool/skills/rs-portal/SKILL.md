# Portal

Пути — от `<rstool>`. Указатель REST — `docs/PORTAL-API.md`.

## Ссылка → API

UI-ссылку (`https://portal.acconcept.ru/rsforms/856?tab=editor`) не открывай и не парси HTML: преобразуй в REST — `https://api.portal.acconcept.ru/api/rsforms/856/details` (query и hash отбрасываются). Правила, поиск, доступ — `docs/PORTAL-READ.md`.

- С API-ключом пользователя: `/api/agents/...` и `Authorization: Bearer rcp_…`.
- Без разрешённого REST-ключа анонимно видны только публичные схемы в `/S` и `/L`. Для непубличной сначала проверь существующую личную привязку и инструменты MCP ниже. Если привязка работает, отсутствие инструмента требует обновления MCP-host, а не нового ключа. При отсутствии доступа предложи штатное подключение или экспорт JSON `/details`; ключ в чат и cookie не запрашивай.
- Нужны только название или доступ — метаданные, не `/details`.

## Чтение и импорт

В HTTP MCP с настроенной Portal-интеграцией проверь каталог. Начиная с адаптера 2.3.0 `portal_search_library` ищет доступные объекты, включая личные; `portal_get_details` читает КС, модель или ОСС. Создание доступно через `portal_create_schema`, `portal_create_model`, `portal_create_oss`, без передачи ключа. Требуются явные `location`, `accessPolicy` и устойчивый `requestId`, модели также `schemaId`. После потери ответа сначала вызови `portal_get_creation_status` и прочитай известный ID либо найди объект поиском. Не меняй requestId ради повтора неопределенной операции. Новые объекты пустые, загрузка содержимого использует отдельный штатный протокол. Подробнее — [протокол MCP](https://github.com/IRBorisov/ConceptPortal/blob/main/rsconcept/rstool-mcp/PORTAL.md).

1. `GET …/rsforms/:id/details` → файл в папке задачи (UTF-8).
2. `importData(payload)` — `auto` распознает JSON Portal; не передавай его как `kind: 'session'`.
3. `listDiagnostics()`; дальше по маршруту (`skills/rstool/SKILL.md`): ревью, развитие.
4. Сохрани сессию-базу (`exportSession`) — для `check-brief --base` и сводки изменений.

Модели — `docs/PORTAL-MODELS.md`; ОСС — `docs/PORTAL-OSS.md`.

## Бриф на Portal

Пока бриф на Portal не хранится (план — блок «Задание» в паспорте схемы): держи `brief.json` в папке задачи. При ревью или развитии схемы Portal без брифа восстанови его (`rs-scope` §«Восстановление брифа»).

## Новая КС и путь

«Папка» библиотеки задаётся строкой `location` самой схемы. Отдельный объект папки или запрос на его создание не нужен. Например, для диплома D00B01 сразу задай `/U/Дипломы/D00B01`; несколько схем этой работы получают тот же путь и разные имена.

Для новой схемы в настроенном HTTP MCP используй `portal_create_schema` с `title`, `alias`, `location`, `accessPolicy` и `requestId`; ключ не передавай. Если этот инструмент отсутствует, используй REST `POST /api/agents/rsforms` с разрешённым API-ключом. Оба пути создают пустую КС и возвращают её ID. Перед первой загрузкой сверь `title` и `alias` экспорта со значениями при создании. Затем загрузи содержимое в этот ID и повторно прочитай `/details`, проверив также название, шифр, путь и доступ. Выбор защищённой записи и обработка незавершённой загрузки описаны в `docs/PORTAL-PUBLISH.md` §«Новая КС».

`createSession` / `create_session` создаёт сессию rstool, а не объект Portal. Каталог конкретного MCP может предоставлять только часть REST API. Отсутствие инструмента создания КС в этом MCP не означает отсутствия операции на портале. При необходимости используй разрешённый REST-доступ; привязанный к MCP ключ не извлекай. Называй точную недостающую возможность или авторизацию, а не «создание папок».

## Замена существующей КС

Для верного источнику аннотированного оригинала, где пользователь требует сохранить содержательные ошибки, не удаляй ошибочные формулы ради публикации. В MCP 2.4.0 схема `portal_prepare_publication` допускает `sourceReview` только для текущих `schemaFormalDuplicate`: отпечаток исходного PDF, точные шифры/коды/хеши выражений, страницы и пояснения, уже сохранённые в конвенциях. Пользователь видит этот разбор и явное предупреждение об ошибочной теории на отдельной странице подтверждения. Никакого MCP-подтверждения или общего `ignoreDiagnostics` нет. Другие ошибки схемы блокируют подготовку. Если поля нет в фактической схеме сервера, назови ограничение; подробности — [протокол аннотированного источника](https://github.com/IRBorisov/ConceptPortal/blob/main/rsconcept/rstool-mcp/PORTAL.md#annotated-sources-with-preserved-formal-duplicates).

Протокол — `docs/PORTAL-PUBLISH.md` §«Протокол публикации»:

1. Работа по этапам, пока `check-brief` не покажет этап `review` без блокеров (или пользователь согласился с «готово частично»).
2. Сводка изменений относительно сессии-базы → **подтверждение пользователя**.
3. Описание схемы содержит назначение, ограничения и краткий журнал решений (гейт `rs-explicate`). `create-version` (если есть права) → `replace` с `exportPortal({ kind: 'schema' })`.
4. Повторно прочитай `/details`, импортируй и сверь. Отчёт со ссылкой на схему в UI.

В настроенном HTTP MCP `portal_get_description(targetId)` читает описание и редакцию привязанным ключом без локальной сессии, в том числе для непубличной схемы. Для правки только комментария схемы используй CAS `/description` или `portal_update_description(targetId, expectedTimeUpdate, description)` настроенного HTTP MCP, см. `docs/PORTAL-PUBLISH.md` §«Только комментарий схемы». Полная замена и rstool-сессия для этого не нужны. Отдельное подтверждение каждой записи комментария на странице публикаций не требуется.

## Расположение и доступ

Путь новой КС задаётся при создании. Для уже существующей владелец или staff меняет `location` и `access_policy` ключом: `PATCH /api/agents/library/:id/set-location` и `set-access-policy`. Редактор эти поля не меняет. В `/L` пишет только staff. Обычный `PATCH /api/library/:id/set-location` ключ не открывает. Подробно — `docs/PORTAL-PUBLISH.md` §«Расположение и политика доступа». Не переноси существующую схему без просьбы пользователя.

## Лимиты

Правки: 30 в минуту, 300 в час; `replace`, `create-version` и создание КС — ещё не больше 15 в час. `429` — бюджет кончился, не повторяй в цикле. Подробно — `docs/PORTAL-PUBLISH.md` §«Лимиты».

## Не делай

- Не заменяй схему без сводки изменений и подтверждения.
- Не предлагай авторизацию через session cookie.
- Не перебирай id подряд — используй контекстный поиск.
