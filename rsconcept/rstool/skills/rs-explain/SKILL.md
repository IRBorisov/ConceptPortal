# Объяснение

Пути — от `<rstool>`. Карточки конструкций и полный сценарий — `docs/CONSTRUCTIONS.md`. Бриф не нужен.

## Шаги

1. **Роль.** Имя, тип и термин конституенты; что она выражает в предметной области (по конвенции и текстовому определению).
2. **Формула как есть** — без переписывания.
3. **Вид выражения:** теоретико-множественное (значение — множество, кортеж, число) или логическое (истина / ложь).
4. **Снаружи внутрь:** главная операция, затем её аргументы; объясняй только конструкции, которые есть в формуле (`docs/CONSTRUCTIONS.md`).
5. **Ступень и опоры:** типизация результата (`labelType`) и от каких конституент формула зависит.
6. **Пример на данных** — только по запросу: маленькая модель подписями (сценарий брифа или `setModelValues` + `evaluate` на копии сессии).

Для учебной схемы — ещё **решения по ядру**: почему выбраны эти неопределяемые понятия и отношения, какие аксиомы есть и каких сознательно нет (журнал решений брифа, если он есть; иначе — как гипотеза).

## Не делай

- Не меняй схему, объясняя её.
- Не используй имена API в тексте: «формальное определение», а не `definitionFormal` (словарь — `skills/rstool-runtime/SKILL.md`).
- Не называй `X#` «базисом», `T#` — «теоремой».
- Не разбирай конструкции, которых нет в формуле.
