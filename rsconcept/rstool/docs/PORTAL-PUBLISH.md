# Portal: публикация схемы

Как от имени пользователя создать КС из rstool, заменить содержимое, снять версию или править конституенты. REST-клиенту нужен API-ключ. Настроенный MCP использует полномочия текущего подключения. [Правила доступа](PORTAL-READ.md#доступ) · [Карта маршрутов](PORTAL-API.md)

## Новая КС

Папки библиотеки являются группировкой элементов по строке `location`. Отдельного объекта папки, её ID или предварительного запроса на создание папки не требуется. Если пользователь просит отдельную папку для диплома, добавь его шифр в путь схемы, например `/U/Дипломы/D00B01`.

С API-ключом, разрешающим создание схемы, выполни:

```http
POST /api/agents/rsforms
Content-Type: application/json
Idempotency-Key: new-d00b01-po1

{
  "title": "D00B01. Предметная область 1",
  "alias": "D00B01-PO1",
  "location": "/U/Дипломы/D00B01",
  "access_policy": "private"
}
```

Добавь `schema` с результатом `exportPortal({ kind: 'schema', format: 'object' })`, чтобы создать КС с содержимым в той же транзакции. Без `schema` Portal создаёт пустую КС. Верхний уровень запроса задаёт название, шифр, комментарий, путь и доступ. Ответ `201` содержит ID. Владелец определяется авторизацией. В `/L` создавать может только staff.

Сохрани возвращённый ID. Перед первой загрузкой проверь, что `title` и `alias` в `exportPortal({ kind: 'schema' })` совпадают с согласованными значениями при создании. Загрузка содержимого записывает эти поля из экспорта и может заменить только что заданные название и шифр.

Для первой загрузки в новую пустую КС независимо авторизованный REST-клиент с правом `write` может использовать один из двух способов:

- Чтобы сохранить снимок до загрузки, прочитай `/details`, проверь, что КС ещё пустая, и возьми `time_update`. Используй `POST /api/agents/rsforms/:id/publish` с `{expected_time_update: time_update, schema: exportPortal(...)}`. Проверка редакции атомарна. При `409` сначала установи, что изменилось.
- Для импорта в собственную пустую КС используй `PATCH /api/agents/rsforms/:id/replace`. Сервер проверяет право владельца и пустоту под блокировкой. Можно передать ревизию в заголовке `X-Expected-Time-Update`. Для замены заполненной КС используй протокол ниже.

После загрузки повторно прочитай `/details` и сверь `title`, `alias`, содержимое, описание, `location` и `access_policy`. Поле пути не дописывается в JSON импорта: загрузка содержимого его не меняет. Для нескольких КС одной работы повтори создание с разными именами и тем же `location`.

Если ответ потерян, начни с квитанции `rsform.create` и сверь объект через `/details`. Если раньше был создан пустой объект, продолжай загрузку на его ID. [Как прочитать квитанцию](#квитанции-и-повтор-запроса)

### Выбор MCP или REST

Проверь каталог подключённого MCP и запусти `portal_preflight` для существующей цели. `portal_create_schema_from_session` создаёт КС с содержимым. `portal_get_creation_status(requestId)` восстанавливает ID. Для записи с другого клиента используй отдельно авторизованный REST. Ключ MCP остаётся в сервисе.

## Протокол публикации

Замена требует прав владельца или staff. Portal проверяет согласованную редакцию, создаёт снимок и заменяет содержимое в одной транзакции. Устаревшая редакция даёт `409`. См. [протокол MCP](../../rstool-mcp/PORTAL.md).

Путь MCP:

1. Выполни `portal_preflight` с `operation: publish` для согласованной цели.
2. Подготовь содержимое в исходной сессии. Проверь бриф (`check-brief` с `--base` на сессию-базу).
3. Подготовь `portal_prepare_publication(targetId)` и покажи возвращённую сводку. Получи явное согласие именно на неё.
4. Передай `publicationId` и `digest` в `portal_apply_publication`. При изменении источника, редакции или метаданных цели подготовь новую сводку и согласуй её.
5. Сверь `verified` и повторное чтение. При потере ответа проверь `portal_get_publication_status(publicationId)`.

Путь для отдельно авторизованного REST-клиента.

1. Прочитай `time_update` из `/details` и согласуй изменения.
2. Вызови `POST /api/agents/rsforms/:id/publish` с `Idempotency-Key`, `expected_time_update`, `expected_target` (`owner`, `location`, `access_policy`) и экспортом в `schema`.
3. При потере ответа проверь квитанцию `rsform.publish`, затем независимо прочитай `/details` и сверь редакцию, метаданные и содержимое. Для этой проверки нужны права `read`.

`exportPortal({ kind: 'schema' })` возвращает `crucial`, `term_forms`, `typification_manual`, `value_is_property` и `attribution`, если они были в импортированной схеме. Правка через `applySchemaPatch`, которая эти поля не задаёт, их не стирает. Конституента, созданная в сессии с нуля, уходит с `crucial: false`, пустыми словоформами и пустой ручной типизацией.

Для правки отдельных собственных конституент используй `/constituents`, `substitute` или `move-cst`. Унаследованную конституенту редактируй в исходной КС. Для замены заполненной схемы используй `publish`.

## Квитанции и повтор запроса

Серверная поддержка видна в `GET /api/agents/capabilities` по значению `mutation_receipts: 1`. Для записи передавай `Idempotency-Key` из 8–128 латинских букв, цифр, дефисов или подчёркиваний. Ключ действует в пределах аккаунта Portal и вида операции. Доступные виды квитанций: `rsform.create`, `model.create`, `oss.create` и `rsform.publish`.

Читай `GET /api/agents/receipts/:operation` с исходным `Idempotency-Key` и авторизацией того же аккаунта. Portal проверяет актуальное право чтения цели. Квитанция содержит `target_id`, `version_id` (для создания `null`), `revision` и `target_metadata` с владельцем, путём и видимостью. `404` означает, что доступной завершённой квитанции сейчас нет. Запись может быть ещё в процессе.

Повтор запроса с тем же ключом, телом и целью возвращает прежний ID. При другом теле или цели сервер возвращает `409`. При успешном повторе `committed_time_update` указывает на записанную редакцию, а данные объекта могут отражать более поздние правки. Сопоставь их с независимым `/details`. Квитанция фиксируется вместе с записью. Запрос записи без ключа остаётся допустимым для совместимости и не создаёт квитанцию.

## Только комментарий схемы

Для порученной правки только `description` не импортируй схему в rstool и не вызывай полную замену. Прочитай `/details`, сохрани `time_update`, затем вызови `POST /api/agents/rsforms/:id/description` с `{expected_time_update, description}`. Нужны обычные права редактирования. Поле может быть пустым, пробелы сохраняются, предел 100000 символов. Другие поля не принимаются. CAS обновляет только описание и время изменения, сохраняет формулы и конституенты, не создаёт версию. Действуют обычные квоты записи. Устаревшая редакция даёт 409 без изменения.

В настроенном HTTP MCP сначала вызови `portal_get_description(targetId)`, затем `portal_update_description(targetId, expectedTimeUpdate, description)` с прочитанным `time_update`. Инструмент повторно читает схему и сверяет описание и остальное содержимое. Ответ содержит `targetId`, `description`, `time_update`. Если ответ потерян, перечитай комментарий и редакцию до повторной записи. Для полной замены используй согласованную публикацию.

## Расположение и политика доступа

Ключ `rcp_…` не открывает `PATCH /api/library/:id/set-location` и `set-access-policy`: те маршруты принимают только сессию сайта. Для агента те же поля у любого элемента библиотеки (КС, ОСС, модель):

```text
PATCH /api/agents/library/:id/set-location
{ "location": "/S/Агентская автоматизация процессов" }

PATCH /api/agents/library/:id/set-access-policy
{ "access_policy": "public" | "protected" | "private" }
```

- Меняет владелец или staff. Редактор содержимого — нет, даже если схема не `read_only`. Флаг `read_only` блокирует правку содержимого, но не эти метаданные.
- В `/L` пишет только staff. `/S`, `/U` и `/P` — по общим правилам пути.
- У ОСС вместе с ней получают то же значение её результаты с тем же владельцем и той же папкой. Чужие схемы и схемы из другой папки не трогаются.
- `time_update` не меняется. `replace` по-прежнему расположение не пишет.
- Ответ — метаданные объекта, как у `GET /api/agents/library/by-ids`.
- Это обычная правка: 30 в минуту и 300 в час, без отдельного потолка 15 в час.

Перенос и смена доступа видны в библиотеке. Делай их по просьбе пользователя.

## Лимиты

Все ключи одного пользователя делят один бюджет. Счётчик лежит в базе, поэтому три воркера gunicorn не умножают лимит.

- Чтение (`GET`): 120 запросов в минуту. В журнал не пишется.
- Правки: 30 в минуту и 300 в час. Успех и ошибка `400` пишутся в журнал.
- Создание КС и моделей, `replace`, `publish` и `create-version`: дополнительно не больше 15 раз в час.
  Сюда же входят правки ОСС, которые создают КС: `POST /api/agents/oss`, `create-schema`,
  `import-schema`, `clone-schema`, `create-synthesis`, `create-input`, `execute-operation`.
- Активных ключей у пользователя: не больше 5.
- `last_used_at` обновляется не чаще раза в минуту.

`429` значит, что бюджет этого окна кончился. Повторять тот же запрос в цикле бессмысленно: новые строки в базе от этого не появятся.

Управление ключами и журналом — только из сессии UI: `GET/POST /api/agents/keys`,
`PATCH /api/agents/keys/:id` (переименовать), `DELETE /api/agents/keys/:id`.
`GET /api/agents/logs?limit=&offset=` возвращает `{count, results}` (`limit` по умолчанию 50,
не больше 200). В строке есть `request_text`. Ключ этот маршрут не открывает.

## Не делай

- Не заменяй схему без показанной сводки и явного согласия пользователя на эту схему.
- Не повторяй запрос в цикле после `429`.
- Не публикуй схему с блокерами `check-brief`, не сказав об этом пользователю.
- Не переноси схему и не меняй `access_policy` без просьбы пользователя.
