# Portal: публикация схемы

Как записать КС из `rstool` в Portal от имени пользователя: создать, заменить содержимое, снять версию, править конституенты. Нужен API-ключ — [PORTAL-READ.md](PORTAL-READ.md) §«API-ключи». Карта маршрутов — [PORTAL-API.md](PORTAL-API.md).

## Новая КС

Папки библиотеки являются группировкой элементов по строке `location`. Отдельного объекта папки, её ID или предварительного запроса на создание папки не требуется. Если пользователь просит отдельную папку для диплома, добавь его шифр в путь схемы, например `/U/Дипломы/D00B01`.

С API-ключом, разрешающим создание схемы, выполни:

```http
POST /api/agents/rsforms
Content-Type: application/json

{
  "title": "D00B01. Предметная область 1",
  "alias": "D00B01-PO1",
  "location": "/U/Дипломы/D00B01",
  "access_policy": "private"
}
```

Это создание **пустой** КС, не импорт `exportPortal`. Ответ `201` содержит ID новой схемы. Владелец определяется авторизацией, поле `owner` не передавай. `location` и `access_policy` задаются независимо; для личного размещения используй согласованную политику доступа. В `/L` создавать может только staff.

Сохрани возвращённый ID. Перед первой загрузкой проверь, что `title` и `alias` в `exportPortal({ kind: 'schema' })` совпадают с согласованными значениями при создании. Загрузка содержимого записывает эти поля из экспорта и может заменить только что заданные название и шифр.

Далее речь только о первой загрузке в возвращённую новую пустую КС. Для независимо авторизованного REST-клиента выбери способ записи:

- Если ключ имеет scope `publish`, прочитай `/details`, проверь, что КС ещё пустая, и возьми `time_update`. Используй `POST /api/agents/rsforms/:id/publish` с `{expected_time_update: time_update, schema: exportPortal(...)}`. Проверка редакции атомарна; при `409` сначала установи, что изменилось, и не повторяй запись с устаревшей базой.
- Без scope `publish` используй `PATCH /api/agents/rsforms/:id/replace` только для непосредственной первой загрузки в созданную тобой пустую КС, пока исключены параллельные правки. `replace` не проверяет `time_update`: чтение `/details` не защищает от записи между чтением и PATCH. Если загрузка отложилась, сначала прочитай текущее состояние; после промежуточных правок не повторяй `replace` по этому сценарию. Применяй протокол замены существующей КС ниже.

После загрузки повторно прочитай `/details` и сверь `title`, `alias`, содержимое, описание, `location` и `access_policy`. Поле пути не дописывается в JSON импорта: загрузка содержимого его не меняет. Для нескольких КС одной работы повтори создание с разными именами и тем же `location`.

Если ответ на создание потерян, сначала найди результат через доступную библиотеку или контекстный поиск. Не повторяй `POST` вслепую. Если создание удалось, а загрузка нет, сохрани ID и точный статус пустой или частично заполненной КС; не создавай ещё одну вместо неё.

### Выбор MCP или REST

Проверь каталог подключённого MCP. `create_session` создаёт сессию rstool, а `portal_prepare_publication` готовит замену известного объекта Portal; эти инструменты не являются `POST /api/agents/rsforms`. Отсутствие нужного MCP-инструмента ограничивает этот адаптер, а не REST API Portal. Для создания можно использовать отдельный разрешённый REST-клиент с подходящей авторизацией.

Привязанный к MCP ключ остаётся внутри сервиса. Не извлекай его и не обходи штатное подтверждение замены через кабинет. Если REST-авторизация недоступна, укажи именно это ограничение и сохрани готовый экспорт с целевым `location`. Не требуй отдельного инструмента создания папок.

## Протокол публикации

Для настроенного HTTP MCP доступен отдельный [процесс подготовки и подтверждения](../../rstool-mcp/PORTAL.md): ключ вводится на защищённой странице самим пользователем, инструмент подготовки только готовит полную замену. Новый `POST /api/agents/rsforms/:id/publish` принимает `{expected_time_update, schema}` и атомарно проверяет базу, сохраняет версию и заменяет содержимое. Устаревшая база даёт 409. Для сохранения версии требуется владелец/staff. Старый `replace` сохраняет прежний контракт; ключ в чат/аргументы MCP не передавать.

1. Прочитай текущую схему: `GET /api/agents/rsforms/:id/details` → `importData` (сессия-база) и запомни `time_update`.
2. Сделай работу в отдельной сессии; проверь бриф (`check-brief` с `--base` на сессию-базу).
3. Покажи пользователю сводку изменений относительно базы (добавлено, изменено, удалено, затронутые требования и решения) и получи подтверждение.
4. Если есть права — `POST /api/agents/rsforms/:id/create-version`: снимок до замены.
5. `PATCH /api/agents/rsforms/:id/replace` с JSON `exportPortal({ kind: 'schema' })`.
6. Повторно прочитай `/details`, импортируй и сверь: число конституент, формулы, диагностики. Отчёт со ссылкой на схему в UI.

`exportPortal({ kind: 'schema' })` возвращает `crucial`, `term_forms`, `typification_manual`, `value_is_property` и `attribution`, если они были в импортированной схеме. Правка через `applySchemaPatch`, которая эти поля не задаёт, их не стирает. Конституента, созданная в сессии с нуля, уходит с `crucial: false`, пустыми словоформами и пустой ручной типизацией.

Гранулярные правки (`/constituents`, `substitute`, `move-cst`) уместны для одной-двух конституент; для пакета правок — `replace`.

## Только комментарий схемы

Для порученной правки только `description` не импортируй схему в rstool и не вызывай полную замену. Прочитай `/details`, сохрани `time_update`, затем вызови `POST /api/agents/rsforms/:id/description` с `{expected_time_update, description}`. Нужны обычные права редактирования. Поле может быть пустым, пробелы сохраняются, предел 100000 символов. Другие поля не принимаются. CAS обновляет только описание и время изменения, сохраняет формулы и конституенты, не создаёт версию. Действуют обычные квоты записи. Устаревшая редакция даёт 409 без изменения.

В настроенном HTTP MCP сначала вызови `portal_get_description(targetId)`, который читает описание и `time_update` привязанным ключом, в том числе для непубличной схемы. Затем используй `portal_update_description(targetId, expectedTimeUpdate, description)`, передав прочитанный `time_update` как `expectedTimeUpdate`. Ключ берётся из существующей привязки, в аргументы не передаётся. Отдельное подтверждение каждой такой записи на странице публикаций не требуется. Полная замена сохраняет прежнее подтверждение. После записи инструмент повторно читает схему и сверяет описание и остальное содержимое; ответ содержит `targetId`, `description`, `time_update`. При ошибке сети или сверки результат может быть неопределённым, повторную запись автоматически не выполняй. Сначала прочитай Портал.

## Расположение и политика доступа

Ключ `rcp_…` не открывает `PATCH /api/library/:id/set-location` и `set-access-policy`: те маршруты принимают только сессию сайта. Для агента те же поля у любого элемента библиотеки (КС, ОСС, модель):

```text
PATCH /api/agents/library/:id/set-location
{ "location": "/S/Агентская автоматизация процессов" }

PATCH /api/agents/library/:id/set-access-policy
{ "access_policy": "public" | "protected" | "private" }
```

- Меняет владелец или staff. Редактор содержимого — нет, даже если схема не `read_only`.
- В `/L` пишет только staff. `/S`, `/U` и `/P` — по общим правилам пути.
- У ОСС вместе с ней получают то же значение её результаты с тем же владельцем и той же папкой. Чужие схемы и схемы из другой папки не трогаются.
- `time_update` не меняется. `replace` по-прежнему расположение не пишет.
- Ответ — метаданные объекта, как у `GET /api/agents/library/by-ids`.
- Это обычная правка: 30 в минуту и 300 в час, без отдельного потолка 15 в час.

Перенос и смена доступа видны в библиотеке. Делай их по просьбе пользователя.

## Лимиты

Все ключи одного пользователя делят один бюджет. Счётчик лежит в базе, поэтому три воркера gunicorn не умножают лимит.

- Чтение (`GET`): 120 запросов в минуту. В журнал не пишется.
- Правки: 30 в минуту и 300 в час. Успех и ошибка `400` пишутся в журнал.
- Создание КС и моделей, `replace`, `publish` и `create-version`: дополнительно не больше 15 раз в час.
  Сюда же входят правки ОСС, которые создают КС: `POST /api/agents/oss`, `create-schema`,
  `import-schema`, `clone-schema`, `create-synthesis`, `create-input`, `execute-operation`.
- Активных ключей у пользователя: не больше 5.
- `last_used_at` обновляется не чаще раза в минуту.

`429` значит, что бюджет этого окна кончился. Повторять тот же запрос в цикле бессмысленно: новые строки в базе от этого не появятся.

Управление ключами и журналом — только из сессии UI: `GET/POST /api/agents/keys`,
`PATCH /api/agents/keys/:id` (переименовать), `DELETE /api/agents/keys/:id`.
`GET /api/agents/logs?limit=&offset=` возвращает `{count, results}` (`limit` по умолчанию 50,
не больше 200). В строке есть `request_text`. Ключ этот маршрут не открывает.

## Не делай

- Не заменяй схему без подтверждения пользователя и без сводки изменений.
- Не повторяй запрос в цикле после `429`.
- Не публикуй схему с блокерами `check-brief`, не сказав об этом пользователю.
- Не переноси схему и не меняй `access_policy` без просьбы пользователя.
