# Portal: интерпретации модели

Чтение и правка концептуальной модели (RSModel) на Portal через API-ключ. Карта маршрутов — [PORTAL-API.md](PORTAL-API.md).

## Интерпретации модели

Для создания модели используй `POST /api/agents/models` с `title`, `alias`, `description`, `location`, `access_policy` и обязательным числовым `schema`, ID доступной для чтения КС. Владелец определяется авторизацией. Права на папку и чтение КС проверяет сервер; отсутствие схемы, недоступная схема и объект другого типа отклоняются. Ответ `201` содержит созданную модель, связанный `schema` и текущие `items`. После создания независимо прочитай `/api/agents/models/:id/details` и проверь связь, метаданные и путь.

В настроенном HTTP MCP 2.3.0 операция `portal_create_model` использует существующую личную привязку, принимает `schemaId` и стабильный `requestId`. Ключ не передаётся в аргументах. Состояние потерянного ответа проверяется через `portal_get_creation_status`; новый запрос создания вслепую не повторять. Подробности [MCP-протокола](../../rstool-mcp/PORTAL.md).

Тело совпадает с сессионными `/api/models/:id/set-value`, `clear-values` и `reset-all`.
Ответ содержит метаданные модели, `schema`
(id связанной КС) и `items[]` с полями `id`, `type`, `value`. На обоих маршрутах чтения
(`/api/agents/models/:id/details` и `/api/models/:id/details`) каждая привязка также содержит:

- `stored_type` — сохранённые метаданные привязки, совпадают с полем `type`.
  Маркер `basic` обозначает словарь элементов базисного множества или константы.
  Движок сохраняет форму структурированных значений с префиксом `shape:`. Например,
  типизации `ℬ(X1×X2)` соответствует запись `shape:ℬ(*×*)`. Звёздочка обозначает
  место элемента базисного множества или целого числа. Замена `X2` на `X1` изменит
  `effective_type` и сохранит ту же форму.
- `effective_type` — действующая типизация конституенты в связанной КС с учётом ручной
  типизации. Она вычисляется при чтении. Для проверки интерпретации используй это поле.
- `type_diagnostic` принимает следующие значения.
  - `null`, если сохранённый тип или форма совпадают с действующими либо маркер `basic`
    соответствует базисному множеству или константе.
  - `normalized_stored_type`, если сохранённая запись в старом формате совпадает с
    результатом прежней нормализации. Например, прежний движок мог сохранить `ℬ(X1×X2)`
    как `ℬ(X1×X1)`. По такой записи нельзя установить, менялась ли типизация КС.
  - `stored_type_mismatch`, если сохранённая запись расходится с действующей типизацией
    и допустимыми формами её хранения.
  - `effective_type_unavailable`, если действующий тип не определён, КС недоступна для
    чтения или анализатор завершился с ошибкой. В этих случаях `effective_type` равно `null`.

После правки КС следующий GET вычисляет тип заново. Клиент может проверить сохранённое
значение по действующей типизации и явно обновить привязку через `set-value`. Формат
записи и файлового переноса привязок использует прежние поля `id`, `type`, `value`;
диагностические поля доступны в ответе GET.

`target` и элементы `items` — id конституент **связанной** КС, не шифры. Чужая конституента
или модель без схемы → `400`. КС, переданная как id модели → `404`. Правка требует права
редактора; чтение — права читателя. Необязательный заголовок `X-Expected-Time-Update`
(значение `time_update` из предыдущего ответа) отклоняет устаревшую запись с `409`.

```bash
curl.exe -s -H "Authorization: Bearer rcp_...." -H "Content-Type: application/json" ^
  -d "[{\"target\": 1201, \"type\": \"basic\", \"data\": {\"1\": \"a\"}}]" ^
  -X POST "https://api.portal.acconcept.ru/api/agents/models/900/set-value"
```

`clear-values` принимает `{ "items": [1201, 1202] }`. `reset-all` — `POST` без тела.

Сначала прочитай `GET /api/agents/models/:id/details`, чтобы взять id связанной КС и id конституент. Проверку смысла схемы на данных удобнее делать локально в `rstool` (сценарии брифа); на Portal пиши уже проверенные интерпретации.
