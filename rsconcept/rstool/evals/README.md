# Eval скиллов rstool

Проверяет, строит ли агент КС, которая **отвечает запросу**, а не только проходит анализатор. План — [`../plans/skills-rework.html`](../plans/skills-rework.html), §12. Папка не входит в npm-пакет.

## Задачи v0

| id                  | тип                     | что даётся                      | ловушка                                             |
| :------------------ | :---------------------- | :------------------------------ | :-------------------------------------------------- |
| `req-conference`    | КС по требованиям       | ТЗ рецензирования докладов      | авторы и рецензенты — разные `X#`; пересказ ТЗ      |
| `req-timetable`     | КС по требованиям       | требования к расписанию         | занятие как кортеж ломает поток; сумма численностей |
| `evolve-tasks`      | развить КС              | сессия v1 + запрос на изменение | ацикличность ослаблена; v1 сломана                  |
| `explicate-friends` | экспликация по описанию | текст «Друзья и враги»          | симметричная дружба; правила как аксиомы            |
| `review-tournament` | ревью КС                | «зелёная» схема с дефектами     | «диагностик нет — всё хорошо»                       |
| `fix-routes`        | починить формулу        | схема с двумя ошибками          | удалить / ослабить аксиому связности                |

В плане для v0 указано 7 задач (2+2+1+1+1) при итоге «6»; в v0 одна задача «развить КС», вторая — в v1.

Состав папки задачи:

- `prompt.md` — запрос пользователя, передаётся агенту дословно;
- `given/` — входные файлы, копируются агенту в `input/`;
- `user.md` — карточка симулятора пользователя (агенту не показывается);
- `reference.md` — скрытый эталон и рубрика (агенту не показывается).

Стартовые сессии `given/start-session.json` собирает `build-start-sessions.ts` (`pnpm exec tsx evals/build-start-sessions.ts` из корня пакета); скрипт проверяет, что в каждой сессии ровно ожидаемые диагностики.

## Прогон

1. Изолированная копия репозитория без `evals/`: `git worktree add --detach <wt> <commit>`, затем `rm -rf <wt>/rsconcept/rstool/evals`, `pnpm install`, сборка `@rsconcept/domain`.
2. Для каждой задачи: `<wt>/.tmp/eval/<task>/input/` ← `given/`, пустой `out/`.
3. Агент-исполнитель (headless, свежий контекст) получает промпт ниже. Скилл, «загруженный хостом», — тот, что проверяется: базовый прогон — `.agents/skills/rstool-helper/SKILL.md`, после переработки — `.agents/skills/rstool/SKILL.md`.
4. Симулятор пользователя: если агент закончил ход вопросами, он получает ответы по `user.md` (вне карточки — «на ваше усмотрение, запишите как допущение»). Не больше трёх обменов. Симулятор не добавляет данные карточки без прямого вопроса и не пишет пустое «продолжайте» — только ответы на заданные вопросы.
5. Судья (отдельный агент) читает `reference.md`, переписку, `out/` и при необходимости запускает rstool на сессии агента; ставит баллы по рубрике и считает нарушения.

### Промпт исполнителя

```text
Ты — агент-помощник в репозитории ConceptPortal по пути <wt>. Хост загрузил
проектный скилл <wt>/<skill-path> — прочитай его и следуй ему.
Работай только внутри <wt>. Папка задачи: <wt>/.tmp/eval/<task>/ (входные файлы
в input/, результаты сохраняй в out/).

Сообщение пользователя:
«<prompt.md>»

Пользователь на связи: если тебе нужно что-то у него спросить, закончи свой ход
вопросами — ответ придёт следующим сообщением. Финальный ответ пиши так, как
написал бы пользователю в чате.
```

## Метрики

- Баллы по рубрике `reference.md` (0–2 за пункт), сумма в % от максимума.
- Нарушения «озеленения» (план §8): удалена/ослаблена аксиома, производное → `S#`, тривиальная формула, непустой `failed`, пустая конвенция.
- Задал ли агент вопросы до формализации; назвал ли невыразимое.
- Стоимость: токены, вызовы инструментов, время (из уведомления о завершении агента: `subagent_tokens`, `tool_uses`, `duration_ms`) — записывать в `transcript.md`.
- Скрипты и артефакты агента — только внутри рабочего дерева прогона.
