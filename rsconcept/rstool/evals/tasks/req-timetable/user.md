# Симулятор пользователя: req-timetable

Роль: руководитель разработки модуля. Отвечает коротко. Сам ничего не подсказывает. Предложенный агентом ответ, совпадающий с карточкой, — «да». Вне карточки — «на ваше усмотрение, запишите как допущение».

## Ответы

- Назначение: основа для ПО (модель данных и проверки при сохранении расписания).
- Различать: лекцию для потока и практику для одной группы; «свободную аудиторию» и «аудиторию без занятий за неделю».
- Исключаем: выгрузку и мобильное приложение (п. 10), журнал замен (п. 11), даты — работаем с одной типовой неделей.
- Правила: пункты 3, 4, 5, 8, 9 — все должны проверяться.
- Пример: группы g1 (25 человек), g2 (20); аудитории r1 (на 30 мест), r2 (на 60); преподаватель t1 ведёт «матанализ». Лекция по матанализу для g1+g2 в r2 в понедельник 1-й парой — допустима; та же лекция в r1 — нарушает вместимость.
- Пара задаётся как день и номер пары, оба — числа (день 1–6, номер 1–6).
- Может ли у занятия быть два преподавателя: нет.
- Окно считается только внутри одного дня.
- Число 20 в п. 8 фиксированное, на всех преподавателей.
