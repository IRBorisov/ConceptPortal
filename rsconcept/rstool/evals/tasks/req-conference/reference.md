# Скрытый эталон: req-conference

Тип: КС по требованиям. Назначение: project.

## Требования к выразительным средствам

| id  | понятие                                            | ref |
| :-- | :------------------------------------------------- | :-- |
| E1  | авторы доклада (многозначно)                       | 2.1 |
| E2  | организации человека (многозначно)                 | 2.1 |
| E3  | назначенные рецензенты доклада                     | 2.2 |
| E4  | конфликт интересов (человек × доклад)              | 2.3 |
| E5  | рецензия с оценкой (рецензент, доклад, оценка ∈ Z) | 2.5 |
| E6  | доклады, ожидающие рецензий                        | 2.7 |
| E7  | принятые доклады                                   | 2.8 |

## Инварианты

| id  | правило                                          |
| :-- | :----------------------------------------------- |
| I1  | нет назначения при конфликте интересов           |
| I2  | у доклада ≥ 3 назначенных рецензентов            |
| I3  | не больше одной рецензии от рецензента на доклад |
| I4  | оценка в диапазоне −2…+2                         |
| I5  | рецензия только от назначенного рецензента       |
| I6  | рецензенты — члены ПК; у доклада есть автор      |

## Различения

- V1 назначение ≠ написанная рецензия (разные структуры, пример: назначен, но не написал).
- V2 ожидающие рецензий ≠ непринятые (доклад без отрицательных, но с ненаписанной рецензией — ожидает; доклад со всеми рецензиями и отрицательной оценкой — не ожидает и не принят).

## Ловушки

- Родовое vs видовое: авторы и члены ПК — разные базисные множества `X#`. Тогда соавторство рецензента (2.3) невыразимо или выражается кривым дублированием. Эталон: одно множество людей, роли — структуры.
- Пересказ: в схеме есть «интерфейс», «уведомления», «оплата», «история», «просроченные рецензии» без упоминания, что это исключено.
- Не названо невыразимое: «просроченная рецензия», «сумма взноса», «история рецензии».
- Оценка через `C#` с кодами вместо `Z` с аксиомой диапазона — допустимо, если обосновано; кодирование статусов доклада в `C#` — дефект.
- Принятие (2.8) через `card(...) > 0` вместо `≠ ∅` — стиль.

## Рубрика (0–2 за пункт)

1. Постановка: зафиксированы назначение, исключения и невыразимое.
2. Вопросы пользователю: заданы до формализации, по существу, с предложенными ответами.
3. Покрытие E1–E7.
4. Инварианты I1–I6 выражены аксиомами.
5. Различения V1–V2 разведены.
6. Ядро: одно множество людей (или явно обоснованный выбор), нет лишних `S#` вместо `D#`.
7. Проверка смысла на КМ: позитив и негатив хотя бы для I1 и E6/E7.
8. Честный отчёт: что покрыто, что нет, допущения.
