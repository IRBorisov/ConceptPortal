# Корпус корректности вычислителя ЯРЭ

Domain CI после сборки запускает расширенную проверку на фиксированных и детерминированно сгенерированных наборах. Вызовы быстрого расчёта сверяются с интерпретатором. Полные результаты отдельно проверяются на совпадение диагностики, диапазонов, стека, числа итераций и попаданий в кэш. В фиксированных случаях есть явно ожидаемые результаты, включая переход через лимит в миллион итераций.

Сравнение различает `-0`, `+0` и `NaN`. Оно сохраняет порядок, дубликаты, вложенность и присутствие элементов массивов. При расхождении отчёт показывает идентификатор случая и первый отличающийся путь. Ошибка сценария, отсутствие проверок или несовпадение дают ненулевой код выхода.

| Набор        | Сценарии                                                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model`      | Первый и повторный пересчёт, эквивалентная загрузка, изменение формулы, запуск зависимостей через функции, удаление привязки, порядок и повторы, `NaN` в общем результате |
| `graph`      | Циклы, направление и порядок рёбер, форма AST, переопределённый итератор, лимит итераций и история раундов «Сапёра»                                                       |
| `relational` | Соединение и проекция, знаковый ноль, изменённый AST, геттеры, порядок, диагностика и счётчики на границе лимита                                                          |
| `typed`      | Группировка, подмножества, непересечение, подсчёт, знак нуля, плотный результат и лимит на 250 001 клетке                                                                 |
| `portal`     | Сохранённые схемы и модели Portal, повторная загрузка, добавление и удаление связей, старые привязки, редакция формулы и полные результаты                                |

## Воспроизведение

Команды выполняются из `rsconcept/domain` на Node.js 26. Для фиксированных тестов нужны только собранный пакет и его рабочие зависимости.

```sh
pnpm run build
node benchmarks/portal-correctness/run-node.mjs --extended
```

По умолчанию интерпретатор и проверяемые точки входа берутся из текущей сборки. Для проверки двух ревизий укажите рабочие деревья с готовыми сборками или бандлы. Ключ `--suite` можно передавать несколько раз. Например, эта команда проверяет эксперимент, который добавляет план соединения, поверх интерпретатора из другой ревизии.

```sh
node benchmarks/portal-correctness/run-node.mjs \
  --reference /path/to/reference/worktree \
  --candidate /path/to/candidate/worktree \
  --suite relational --extended
```

Для Portal бандлы обоих вариантов используют один штатный `loadRSForm` из рабочего дерева стенда. Подготовьте архив снимков с `manifest.json` из стенда `portal-corpus`. Исходные ответы Portal загружаются локально и остаются за пределами репозитория. Параметр `--portal-mode full` проверяет первый расчёт экспериментального движка. С режимом по умолчанию `incremental` сверяется инкрементальный пересчёт. Для старых сборок без `recalculateChanged` выбирайте только соответствующие наборы.

```sh
node benchmarks/portal-correctness/bundle.mjs /path/to/reference/worktree /path/to/reference.mjs /path/to/esbuild/lib/main.js
node benchmarks/portal-correctness/bundle.mjs /path/to/candidate/worktree /path/to/candidate.mjs /path/to/esbuild/lib/main.js
node benchmarks/portal-correctness/run-node.mjs \
  --reference /path/to/reference.mjs --candidate /path/to/candidate.mjs \
  --snapshot /path/to/snapshot --extended
```

Для Chromium обслуживайте каталог стенда, бандлы и снимок через один локальный HTTP-сервер. Страница `index.html` принимает URL через `reference`, `candidate` и `snapshot`. URL снимка оканчивается на `/`. Параметры `suite`, `extended` и `portal-mode` совпадают с CLI.

## Экспериментальные ядра

При проверке ядра, подключаемого без интеграции в движок, передайте модуль через `--experiments` или через URL-параметр `experiments`. Он может экспортировать синхронные функции:

- `runRounds({ engine, schemaDetails, modelDetails, constituentId })` для истории раундов. Движок уже загрузил входы и вычислил зависимости. Хук возвращает значение `D8` или `undefined` для перехода на обычный вычислитель.
- `relational({ runtime, operation, expression, functionDefinition, bindings })` для числовой группировки, подмножества, непересечения или подсчёта. Хук возвращает обычное значение `Value`. `undefined` передаёт случай интерпретатору.
- `minesD4({ runtime, model, ids, expression })` для подсчёта соседей «Сапёра». Для отказа от плана используется `undefined`.

Каждый запрошенный хук должен принять хотя бы один случай. Фикстуры с известными расхождениями проверяются на ожидаемую семантику интерпретатора, поэтому исходный ошибочный прототип завершает прогон с ошибкой. Для включаемых планов дополнительно запускайте сборку кандидата на сохранённом корпусе.
