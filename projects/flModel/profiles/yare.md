# Профиль разбора ЯРЭ

Этот документ содержит особенности ЯРЭ. Они не являются универсальными требованиями ко всем формальным языкам.

## Проверка синтеза при наличии экспликаций

Если у задействованных в синтезе КС есть экспликации на ЯРЭ, проверяй таблицу отождествлений средствами `@rsconcept/domain`. Это уточнение автора относится только к ЯРЭ. Строить отдельную экспликацию другого языка ради применения этого валидатора не требуется.

В текущем коде проверка реализована классом `SubstitutionValidator` из `@rsconcept/domain/library/oss-api`. На вход подаются проанализированные исходные КС, включая типизации и графы зависимостей, и таблица отождествлений по идентификаторам конституент. Одна таблица без этих данных не содержит всех необходимых сведений.

```ts
import { SubstitutionValidator } from '@rsconcept/domain/library/oss-api';

const validator = new SubstitutionValidator(schemas, substitutions);
const valid = validator.validate();
const diagnostics = validator.errors;
```

Сохраняй и анализируй как результат проверки, так и весь список диагностик. Значение `true` не гарантирует пустой список: диагностика несовпадения формальных выражений может сопровождать успешный результат проверки.

По текущему коду валидатор проверяет, в частности:

- наличие конституент таблицы и допустимость сочетаний их типов;
- циклы, возникающие в зависимостях типизаций после отождествлений;
- логические циклы в формальных определениях после подстановок;
- согласованность типизаций с учётом таблицы;
- совпадение определений сопоставляемых производных понятий в предусмотренных случаях.

Границы проверки задаются реализацией валидатора. Его результат не заменяет содержательное обоснование того, почему понятия следует отождествить в данной предметной интерпретации и задаче.

Для подтверждения условий используй допустимый и недопустимый сценарии и явно отмечай, какие проверки исполнены. В рамках текущего уточнения инструкций код был прочитан; новая таблица отождествлений не предоставлялась и новый синтез не выполнялся.
