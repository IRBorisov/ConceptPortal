Product configuration & BOM validity

Validate configurable products: which options may combine, which components are required, and whether a configuration yields a buildable bill of materials.

Business purpose

Stop invalid quotes/orders by checking configurations against a formal product schema before ERP commit.

Actors: Product manager, configurator engineer, sales ops, manufacturing planner.

Why ЯРЭ + Concept Portal

  • Compatibility and requirements are constraints over option sets — axioms and predicates fit.
  • BOM explosion becomes term-functions from chosen options to parts.
  • Portal holds the product family schema; sales tools evaluate a КМ per quote.

Conceptual core (sketch)

Неопределяемые понятия

S4ℬ(X1×X2) — mandatory options for family

Производные / проверки

AliasIntent
F1Parts implied by a chosen option set
P1Chosen set has no incompatible pair from S2
P2All mandatory options for family are chosen

T1Buildable ⇔ P1 ∧ P2

Aliases are a starting sketch for conceptualization — refine with BASE-SELECTION and avoid new X#/C#/S# when a D#/F#/P# suffices.

Concept Portal usage

  • One КС per product line or a shared catalog with family parameter.
  • Version on major catalog releases; synthesize shared Parts schema via ОСС.
  • Sales agent workflow: import schema → set chosen options as model values → evaluate T1.

rstool-helper delivery workflow

  1. Interview PM for incompatibilities and mandatories only (предметная редукция).
  2. Patch S2/S4 carefully; avoid inventing options not in source.
  3. КМ: 2 valid + 2 invalid configs; recalculateModel.
  4. Publish Portal; document conventions for option meaning.

Tooling loop

ensureSession → applySchemaPatch (core X/C/S)
analyzeExpression → patch D/F/P/A/T
setModelValues → evaluate / recalculateModel
listDiagnostics → fix → commitStep
exportPortal({ kind: 'schema' | 'model' }) → Portal library

MVP roadmap

  1. Incompatibility + mandatory checks
  2. BOM quantity rollup F1
  3. Multi-family synthesize
  4. Quote API: return missing mandatories / conflicting pairs

Risks & reductions

  • Treating quantities as X# — use Z in tuples.
  • Copying ERP BOM XML into undefined concepts instead of deriving D#/F#.

Success criteria

Schema ready

No expression/schema diagnostics; conventions in business language; review checklist passed.

Operations adopted

At least one consumer evaluates the key predicate/statement on real sample data; Portal version pinned in the runbook.
